## 1. Agent 常见问题

### 1.1 幻觉（Hallucination）

**问题：** LLM 自信地编造不存在的信息。

```
表现：
  - 编造不存在的工具调用结果
  - 虚构 API 返回值
  - 引用不存在的文档/论文

为什么危险：
  Agent 的后续决策基于工具返回的结果
  → 如果工具结果是 LLM 编造的 → 后续推理全错

示例：
  用户："帮我查一下订单 999999"
  Agent Thought: "需要查订单"
  Agent Action: query_order("999999")
  （工具返回：订单不存在）
  但如果 LLM 直接编造：
  Agent: "您的订单 999999 已发货，预计明天送达"
  → 完全是编的！

为什么会出现：
  1. LLM 的本质是概率预测，不是事实检索
  2. Agent 的 Prompt 太长，LLM 可能"忘记"要调工具
  3. LLM 倾向于给出"看起来合理"的答案
```

**解决方案：**

```python
"""
防幻觉策略
"""

# 策略 1：强制工具调用（不让 LLM 直接回答事实性问题）
SYSTEM_PROMPT = """你是订单查询助手。
规则：
1. 关于订单的任何问题，必须调用 query_order 工具查询
2. 绝对不能凭记忆回答订单信息
3. 如果工具返回"未找到"，如实告知用户
"""

# 策略 2：结果校验（检查工具是否真的被调用了）
class SafeAgent:
    def run(self, user_input: str) -> str:
        for step in range(self.max_steps):
            response = self.llm(self.build_prompt())

            if response.wants_tool_call:
                # 真的执行工具（不是 LLM 编造结果）
                result = self.execute_tool(response.tool_call)
                # 校验结果不是空
                if not result:
                    return "查询失败，请重试"
            else:
                # LLM 直接给回答——检查是否有事实性声明
                if self._contains_factual_claims(response.text):
                    if not self._has_tool_support(response.text):
                        # 有事实性声明但没有工具支持 → 可能是幻觉
                        return self._ask_for_verification(response.text)
                return response.text

    def _contains_factual_claims(self, text: str) -> bool:
        """检查文本是否包含事实性声明"""
        factual_keywords = ["订单", "金额", "状态", "日期", "价格"]
        return any(kw in text for kw in factual_keywords)

    def _has_tool_support(self, text: str) -> bool:
        """检查是否有工具调用支撑"""
        return len(self.tool_results) > 0


# 策略 3：Grounding（让 LLM 标注信息来源）
ANSWER_PROMPT = """基于以下工具返回的结果回答用户问题。
要求：
1. 只使用工具返回的信息
2. 如果信息不足，说"信息不足"
3. 在回答末尾标注信息来源"""
```

### 1.2 死循环

**问题：** Agent 反复执行相同的操作，永远不停止。

```
表现：
  Step 1: Action: search("天气") → 无结果
  Step 2: Action: search("天气") → 无结果
  Step 3: Action: search("天气") → 无结果
  ...
  Step 100: Action: search("天气") → 无结果

为什么出现：
  1. 工具始终返回错误/空结果，LLM 不知道换策略
  2. LLM 陷入"重复同一个 Action"的模式
  3. 没有设置最大步数限制
```

**解决方案：**

```python
"""
防死循环策略
"""

class LoopSafeAgent:
    def __init__(self, max_steps=6, max_repeated=2):
        self.max_steps = max_steps          # 最大总步数
        self.max_repeated = max_repeated    # 同一工具最大连续调用次数
        self.action_history = []            # 记录历史 Action

    def run(self, user_input: str) -> str:
        for step in range(self.max_steps):
            response = self.llm(self.build_prompt())

            if response.wants_tool_call:
                action_key = f"{response.tool_name}:{json.dumps(response.tool_args)}"

                # 检测重复调用
                repeat_count = sum(
                    1 for a in self.action_history
                    if a == action_key
                )

                if repeat_count >= self.max_repeated:
                    # 同一工具被调太多次 → 换策略或终止
                    return self._handle_loop(action_key)

                self.action_history.append(action_key)
                result = self.execute_tool(response.tool_call)

            else:
                return response.text

        # 超过最大步数
        return self._handle_timeout()

    def _handle_loop(self, action_key: str) -> str:
        """处理循环"""
        # 策略 1：换一个工具
        # 策略 2：修改 Prompt，引导 LLM 换思路
        # 策略 3：直接返回当前已知信息
        return "抱歉，我无法获取到相关信息。请尝试换个方式描述您的需求。"

    def _handle_timeout(self) -> str:
        """处理超时"""
        # 返回已经收集到的信息
        if self.collected_info:
            return f"任务执行超时。已收集到的信息：{self.collected_info}"
        return "任务执行超时，请重试或简化您的问题。"
```

### 1.3 工具滥用

**问题：** LLM 调用不必要的工具，或者在不需要工具时强行调用。

```
表现：
  用户："1+1等于几？"
  Agent: Action: calculator(expression="1+1") → "2"
  → 完全可以直接回答，不需要调工具

  用户："你好"
  Agent: Action: search("如何打招呼") → ...
  → 完全不需要调工具

为什么出现：
  1. Prompt 中强调"你有工具"，LLM 倾向于使用工具
  2. 工具描述太模糊，LLM 误以为需要使用
  3. LLM 不善于判断"什么时候不需要工具"
```

**解决方案：**

```python
"""
防工具滥用策略
"""

# 策略 1：Prompt 中明确"不必要时不调工具"
SYSTEM_PROMPT = """你是一个智能助手。

重要规则：
1. 简单问题直接回答，不需要使用工具
2. 只有当你的知识不够、需要实时数据、或需要精确计算时才使用工具
3. 判断标准：如果你能自信地回答，就不要调工具

不需要工具的例子：
- "Python 是什么？" → 直接回答
- "1+1=？" → 直接回答
- "帮我写个排序算法" → 直接回答

需要工具的例子：
- "北京今天天气？" → 需要调天气API
- "123*456=？" → 需要调计算器（大数计算）
- "最新的 LangChain 版本？" → 需要搜索
"""

# 策略 2：工具调用成本计数
class CostAwareAgent:
    def __init__(self, tool_cost_limit=5):
        self.tool_call_count = 0
        self.tool_cost_limit = tool_cost_limit

    def should_use_tool(self, llm_decision) -> bool:
        """判断是否真的需要调工具"""
        if self.tool_call_count >= self.tool_cost_limit:
            return False  # 超过调用限制

        # 简单问题不需要工具
        if llm_decision.confidence > 0.9:
            return False  # LLM 很自信，不需要工具

        return True
```

## 2. 性能优化

### 2.1 Token 控制

```
Token 是 Agent 的核心成本指标。

Agent 一次请求的 Token 构成：
  System Prompt:        ~500 Token
  工具描述（5个工具）:   ~1000 Token
  Memory（对话历史）:     ~2000 Token
  用户输入:              ~100 Token
  ────────────────────────────
  输入总计:              ~3600 Token

  每一步 LLM 输出:      ~200 Token
  工具结果:              ~300 Token
  ────────────────────────────
  每步新增:              ~500 Token

  5 步 Agent:            ~3600 + 5×500 = ~6100 Token 输入
  + 5×200 = ~1000 Token 输出
  总计 ~7100 Token ≈ $0.04（GPT-4o）

对比：
  单次 LLM 调用:        ~600 Token ≈ $0.003

  Agent 的成本是单次调用的 10-20 倍！
```

**Token 优化策略：**

```python
"""
Token 优化策略
"""

# 策略 1：压缩工具描述
# 差（冗长）：
{
    "name": "query_order",
    "description": "这个工具用于根据订单号查询订单的详细信息，包括订单的状态、金额、商品列表、物流信息、支付信息等。当用户询问关于订单的问题时，你应该使用这个工具来获取订单的实时数据。注意：订单号必须是纯数字。"
}
# Token: ~120

# 好（精简）：
{
    "name": "query_order",
    "description": "根据订单号查询订单详情（状态/金额/物流）。用于订单相关问题。"
}
# Token: ~30（节省 75%）


# 策略 2：Memory 压缩
class TokenEfficientMemory:
    """Token 高效的 Memory 管理"""

    def __init__(self, max_tokens=3000):
        self.max_tokens = max_tokens
        self.messages = []

    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        self._trim_if_needed()

    def _trim_if_needed(self):
        """超预算时压缩"""
        while self._estimate_tokens() > self.max_tokens:
            if len(self.messages) <= 2:
                break
            # 删除最旧的非 system 消息
            self.messages.pop(1)

    def _estimate_tokens(self) -> int:
        """粗略估算 Token 数（中文约 1.5 Token/字）"""
        total = 0
        for msg in self.messages:
            total += len(msg["content"]) * 1.5
        return int(total)


# 策略 3：并行工具调用
# 如果多个工具调用之间没有依赖关系，可以并行执行

import asyncio

async def execute_tools_parallel(tool_calls: list) -> list:
    """并行执行多个独立的工具调用"""
    tasks = [execute_single_tool(tc) for tc in tool_calls]
    results = await asyncio.gather(*tasks)
    return results

# 普通 Agent：3 个工具顺序执行 = 3 × 延迟
# 并行 Agent：3 个工具同时执行 = 1 × 延迟
```

### 2.2 调用链优化

```
优化 Agent 的调用链，减少不必要的 LLM 调用

策略 1：提前终止
  如果工具返回的结果已经足够，不需要继续调 LLM
  → 在 Prompt 中加"如果信息已经足够，直接给出最终回答"

策略 2：缓存工具结果
  相同的工具调用，短时间内不需要重复执行
  → 加一层 LRU Cache

策略 3：路由前置
  简单问题不需要走 Agent 循环
  → 先用一个小模型做意图识别
  → 简单问题直接回答，复杂问题才进 Agent

策略 4：流式输出
  Agent 的最终回答用流式输出
  → 用户不需要等 Agent 完全执行完才开始看结果
```

```python
"""
调用链优化：路由前置 + 缓存
"""

from functools import lru_cache
from enum import Enum

class Route(Enum):
    DIRECT = "direct"          # 直接回答
    SINGLE_TOOL = "single"     # 单次工具调用
    AGENT = "agent"            # 完整 Agent 循环

class SmartRouter:
    """智能路由：根据问题复杂度选择处理方式"""

    def route(self, user_input: str) -> Route:
        """判断问题需要什么级别的处理"""
        # 简单判断逻辑（实际项目中可以用小模型）
        simple_patterns = [
            "你好", "谢谢", "再见",
            "什么是", "解释一下", "帮我写",
        ]

        tool_patterns = [
            "天气", "搜索", "查询", "计算",
            "帮我查", "帮我搜",
        ]

        for p in simple_patterns:
            if p in user_input:
                return Route.DIRECT

        for p in tool_patterns:
            if p in user_input:
                return Route.SINGLE_TOOL

        return Route.AGENT


class CachedToolExecutor:
    """带缓存的工具执行器"""

    @lru_cache(maxsize=100)
    def _cached_execute(self, tool_name: str, args_hash: str):
        """缓存的工具执行"""
        pass  # 实际执行

    def execute(self, tool_name: str, args: dict):
        args_hash = str(sorted(args.items()))
        return self._cached_execute(tool_name, args_hash)
```

## 3. 工程实践：设计可扩展的 Agent 系统

### 3.1 架构原则

```
设计可扩展 Agent 系统的 6 个原则：

1. 配置驱动（Configuration-driven）
   → 工具、Prompt、模型都通过配置文件管理，不改代码
   → 新增工具 = 加一行配置

2. 插件化（Plugin Architecture）
   → 工具以插件形式注册，即插即用
   → 新增能力 = 写一个插件

3. 观测性（Observability）
   → 每一步决策都有日志
   → 可以追踪：LLM 输入了什么、输出了什么、调了什么工具

4. 容错性（Fault Tolerance）
   → 单个工具失败不影响整体
   → 有 Fallback 机制

5. 流量控制（Rate Limiting）
   → 控制 LLM 调用频率
   → 控制工具调用频率

6. 版本管理（Version Control）
   → Prompt 版本化
   → 工具版本化
```

### 3.3 插件化工具注册的 Python 实现

```python
"""
插件化工具注册系统
新增工具 = 写一个函数 + 加装饰器，不需要改任何其他代码
"""

from dataclasses import dataclass, field
from typing import Callable, Dict, Optional
import json


@dataclass
class ToolDefinition:
    """工具定义"""
    name: str
    description: str
    parameters_schema: dict
    function: Callable
    category: str = "general"
    cache_ttl: int = 0          # 缓存时间（秒），0 表示不缓存
    rate_limit: int = 0         # 调用频率限制（次/分钟），0 表示不限制
    require_auth: bool = False  # 是否需要认证


class ToolRegistry:
    """
    工具注册中心

    设计理念：
    - 装饰器注册：开发者只需加 @tool 装饰器
    - 分类管理：工具按类别组织
    - 动态发现：运行时自动发现所有注册的工具
    """

    def __init__(self):
        self._tools: Dict[str, ToolDefinition] = {}

    def register(self, name: str, description: str,
                 parameters_schema: dict = None,
                 category: str = "general", **kwargs):
        """装饰器：注册工具"""
        def decorator(func: Callable):
            tool_def = ToolDefinition(
                name=name,
                description=description,
                parameters_schema=parameters_schema or {},
                function=func,
                category=category,
                **kwargs,
            )
            self._tools[name] = tool_def
            return func
        return decorator

    def get(self, name: str) -> Optional[ToolDefinition]:
        """获取工具"""
        return self._tools.get(name)

    def get_all_by_category(self, category: str) -> list:
        """按类别获取工具"""
        return [
            t for t in self._tools.values()
            if t.category == category
        ]

    def get_tool_descriptions(self) -> str:
        """生成给 LLM 看的工具描述（拼入 Prompt）"""
        descriptions = []
        for tool in self._tools.values():
            desc = f"- {tool.name}: {tool.description}"
            if tool.parameters_schema:
                params = ", ".join(tool.parameters_schema.keys())
                desc += f" 参数：({params})"
            descriptions.append(desc)
        return "\n".join(descriptions)

    def get_openai_tools_schema(self) -> list:
        """生成 OpenAI Tool Calling 格式的 Schema"""
        return [
            {
                "type": "function",
                "function": {
                    "name": tool.name,
                    "description": tool.description,
                    "parameters": tool.parameters_schema,
                }
            }
            for tool in self._tools.values()
        ]


# ---- 全局注册中心 ----
registry = ToolRegistry()


# ---- 注册工具（插件化，新增工具只需加装饰器）----

@registry.register(
    name="search_web",
    description="搜索互联网信息。用于查找新闻、事实、数据。",
    parameters_schema={
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "搜索关键词"}
        },
        "required": ["query"]
    },
    category="information",
)
def search_web(query: str) -> str:
    """搜索网页"""
    return f"搜索 '{query}' 的结果..."


@registry.register(
    name="get_weather",
    description="查询城市天气。用于天气相关问题。",
    parameters_schema={
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "城市名"}
        },
        "required": ["city"]
    },
    category="information",
    cache_ttl=300,  # 天气数据缓存 5 分钟
)
def get_weather(city: str) -> str:
    """查天气"""
    return f"{city}: 晴 25°C"


@registry.register(
    name="execute_code",
    description="执行 Python 代码。用于计算、数据处理。",
    parameters_schema={
        "type": "object",
        "properties": {
            "code": {"type": "string", "description": "Python 代码"}
        },
        "required": ["code"]
    },
    category="computation",
    rate_limit=10,       # 限制每分钟 10 次
    require_auth=True,   # 需要认证
)
def execute_code(code: str) -> str:
    """执行代码"""
    return "执行结果..."


# ---- 使用 ----

# 获取工具描述（给 LLM 看）
print(registry.get_tool_descriptions())

# 获取 OpenAI Schema（给 API 用）
print(json.dumps(registry.get_openai_tools_schema(), indent=2, ensure_ascii=False))

# 执行工具
tool = registry.get("search_web")
result = tool.function(query="LangChain")
```

### 3.4 Agent 系统的配置化

```python
"""
```

## 4. 生产级 Agent 的 Checklist

```
上线前检查清单：

□ 安全性
  □ 工具调用有权限控制
  □ 用户输入有校验和清洗
  □ 敏感信息不进日志
  □ 有防注入机制（Prompt Injection）

□ 可靠性
  □ 最大步数限制（防死循环）
  □ 超时控制
  □ 工具调用有重试机制
  □ 有 Fallback 方案（Agent 失败时的兜底）

□ 可观测性
  □ 每步决策有日志
  □ Token 消耗有统计
  □ 工具调用有追踪
  □ 错误有告警

□ 性能
  □ Token 预算管理
  □ 工具结果有缓存
  □ 有路由前置（简单问题不走 Agent）
  □ 有并发控制

□ 成本
  □ LLM 调用有预算上限
  □ 单次请求成本有监控
  □ 有降级策略（成本超标时切小模型）
```

## 5. 常见误区

| 误区 | 真相 |
|------|------|
| "Agent 可以完全自主运行" | 生产环境必须有护栏：步数限制、人工确认、Fallback |
| "性能优化就是减少 Token" | Token 只是成本，延迟和可靠性同样重要 |
| "微服务架构适合所有 Agent 系统" | 简单 Agent 用单体就好，过度架构增加复杂度 |
| "Agent 不需要测试" | Agent 的不确定性更高，更需要测试（Mock 工具 + 回归测试） |
| "上线了就不用管了" | Agent 需要持续监控和调优（Prompt 调优、工具优化、成本控制） |
