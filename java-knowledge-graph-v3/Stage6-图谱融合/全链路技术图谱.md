## 一、Java 技术全链路图（最终形态）

```
用户请求：GET /api/articles/1001
│
├── [1] DNS 解析 → CDN 静态资源
│   └── 网络基础（M13）：DNS/HTTP/TCP
│
├── [2] Nginx 反向代理 + 负载均衡
│   └── IO/NIO（M5）：epoll 多路复用
│
├── [3] Spring Cloud Gateway
│   ├── 鉴权（JWT 校验）
│   ├── 限流（Sentinel）
│   └── 路由转发
│   └── 微服务（M11）：网关/路由/过滤器
│   └── 分布式（M12）：限流算法
│
├── [4] Tomcat 线程接收请求（NIO 模型）
│   ├── IO/NIO（M5）：NIO/Reactor 模式
│   └── 并发（M3）：线程池（Tomcat 默认 200 线程）
│
├── [5] Spring MVC 处理
│   ├── DispatcherServlet 9 步流程
│   ├── Filter 链（编码/跨域）
│   ├── Interceptor 链（鉴权/日志）
│   └── Controller → 返回 JSON
│   └── Spring（M6）：MVC/拦截器/统一异常
│
├── [6] AOP 切面处理
│   ├── @Transactional 事务控制
│   ├── 日志切面（@Around）
│   └── 代理对象（JDK/CGLIB）
│   └── Spring（M6）：AOP/事务/代理
│
├── [7] Service 业务逻辑
│   ├── 参数校验
│   ├── 先查 Redis 缓存
│   │   ├── 命中 → 直接返回（快！）
│   │   └── 未命中 → 查 DB → 写缓存
│   └── Redis（M8）：Hash/缓存策略/击穿防护
│
├── [8] MyBatis 执行 SQL
│   ├── MapperProxy 动态代理
│   ├── 一级缓存（SqlSession）
│   ├── SQL 执行（#{ }防注入）
│   └── 结果映射（ResultSetHandler）
│   └── MyBatis（M9）：执行流程/缓存/动态SQL
│
├── [9] MySQL 执行查询
│   ├── InnoDB 存储引擎
│   ├── B+ 树索引定位
│   ├── MVCC 快照读
│   ├── 行锁/间隙锁
│   └── 返回结果
│   └── MySQL（M7）：索引/事务/锁/MVCC
│
├── [10] 返回路径（逆向）
│   ├── MyBatis 结果映射 → Java 对象
│   ├── Redis 写入缓存（TTL + 随机偏移）
│   ├── Spring MVC 序列化 JSON
│   └── HTTP 响应返回用户
│
└── [异步链路] 文章发布后
    ├── Kafka 发送消息
    │   └── MQ（M10）：可靠性/幂等/积压
    ├── 搜索服务建索引（ES）
    ├── AI 服务生成摘要
    └── 链路追踪（SkyWalking）
        └── 分布式（M12）：分布式事务/CAP

底层贯穿始终：
┌────────┐ ┌────────┐ ┌────────┐
│Java基础│ │  JVM   │ │并发+锁 │
│ (M1)   │ │ (M2)   │ │(M3+M4) │
└────────┘ └────────┘ └────────┘
```

## 二、面试准备路线

### Phase 1：基础阶段（必须掌握，2-3 周）

```
目标：能回答所有"必考"问题，不卡壳

每日时间分配（4-5小时）：
├── 1.5h 看文档/视频（理解原理）
├── 1.5h 整理笔记（用自己的话重述）
└── 1.5h 模拟面试（自问自答/录音）

必过知识点（按优先级）：
Day 1-3:  HashMap 底层 / ConcurrentHashMap / ArrayList
Day 4-6:  JVM 内存结构 / GC 算法 / 类加载
Day 7-10: synchronized / AQS / 线程池 / volatile
Day 11-13: Spring IOC / AOP / 事务 / 循环依赖
Day 14-17: MySQL 索引 / 事务 / MVCC / 锁
Day 18-21: Redis 数据结构 / 缓存三大问题 / 一致性

检验标准：
  ✅ 每个知识点能不看书讲 3 分钟
  ✅ 追问 2-3 次不卡壳
  ✅ 能画核心流程图（AQS/HashMap/Spring MVC）
```

### Phase 2：强化阶段（项目结合，2 周）

```
目标：每个知识点都能结合项目讲

方法：用博客+AI系统做载体，给每个知识点找项目映射

强化清单：
├── HashMap → 本地缓存（Caffeine 底层用 ConcurrentHashMap）
├── 线程池 → AI 调用独立线程池，参数怎么设的
├── 分布式锁 → 文章编辑锁，Redisson 看门狗
├── Redis 缓存 → 文章详情缓存，遇到过击穿问题
├── MySQL 索引 → article 表索引设计，做过慢查询优化
├── Spring 事务 → 文章发布多表操作，事务失效踩过坑
├── Kafka → 文章发布事件，消息幂等消费
└── JVM → 线上 OOM 排查经验

每条必须能讲：
  1. 场景是什么（业务背景）
  2. 问题是什么（遇到什么坑）
  3. 方案是什么（技术选型和原因）
  4. 效果是什么（量化数据）

检验标准：
  ✅ 任意知识点都能讲一个项目案例
  ✅ 能讲清"为什么选这个方案"
  ✅ 能讲清方案的 trade-off
```

### Phase 3：冲刺阶段（面试表达，1 周）

```
目标：面试中流畅表达，会引导面试官

训练方法：
1. 模拟面试（找同学/录音）
2. 每个知识点练 3 分钟结构化表达
3. 准备 3 个"引导点"（引导面试官追问你擅长的）

答题模板（五步法）：
  1. 是什么（10 秒定义）
  2. 为什么（30 秒背景）
  3. 怎么实现（1-2 分钟原理）
  4. 有什么问题（30 秒局限性）
  5. 生产怎么用（30 秒实战经验）

引导技巧：
  讲到 Redis 时："在我们的项目中，我用 Redis 做了 XX，这个过程中遇到了 YY 问题..."
  → 引导面试官追问你准备好的问题

  讲到线程池时："我之前做过一次线上排查，因为线程池参数设置不当导致 ZZ..."
  → 引导到 JVM 调优话题
```

## 三、项目升级建议

### 升级 1：加缓存（Redis）

| 维度 | 内容 |
|------|------|
| **为什么（面试价值）** | 展示高并发设计能力，面试必问缓存方案 |
| **怎么做（技术点）** | Spring Cache + Redis + Cache Aside 模式 |
| **面试怎么讲** | "我在项目中引入了多级缓存：Caffeine 本地缓存（L1，1000 条，5 分钟）+ Redis 分布式缓存（L2，1 小时 + 随机偏移）。解决了热点文章的缓存击穿问题，用 Redisson 分布式锁保证只有一个线程重建缓存。上线后 DB 压力下降 80%，P99 从 200ms 降到 50ms。" |

### 升级 2：加异步（MQ）

| 维度 | 内容 |
|------|------|
| **为什么** | 展示系统解耦和异步设计能力 |
| **怎么做** | Kafka + Spring Event + 本地消息表 |
| **面试怎么讲** | "文章发布后需要通知搜索服务建索引、AI 服务生成摘要。从同步调用改为 Kafka 异步，系统解耦且发布接口响应时间从 800ms 降到 200ms。通过本地消息表保证消息不丢失，消费者用唯一键实现幂等。消息积压过一次，通过增加 partition + 消费者实例解决。" |

### 升级 3：加限流

| 维度 | 内容 |
|------|------|
| **为什么** | 展示高可用保护能力 |
| **怎么做** | Sentinel + Gateway 限流 + Redis + Lua 分布式限流 |
| **面试怎么讲** | "网关层用 Sentinel 做全局限流（QPS 500），AI 接口用 Redis + Lua 脚本做用户级限流（每分钟 10 次）。限流算法用的滑动窗口，比固定窗口更平滑。被限流时返回 429 + 友好提示。上线后系统再没被突发流量打崩过。" |

### 升级 4：加日志链路

| 维度 | 内容 |
|------|------|
| **为什么** | 展示线上排障能力，加分项 |
| **怎么做** | MDC + TraceId + SkyWalking + ELK |
| **面试怎么讲** | "每个请求通过网关时生成 TraceId，通过 HTTP Header 传递到下游服务，用 MDC 注入日志。配合 SkyWalking 做链路追踪，可以在 ELK 中通过 TraceId 查到一个请求在所有服务的完整日志。排查线上问题从小时级降到分钟级。" |

## 四、面试频率 + 难度矩阵

```
                    高频                             低频
            ┌──────────────────┬──────────────────┐
  高难度    │ HashMap底层       │ ZGC原理          │
            │ AQS源码          │StampedLock       │
            │ MVCC原理         │Netty模型         │
            │ GC调优           │一致性哈希        │
            ├──────────────────┼──────────────────┤
  中难度    │ synchronized升级  │IO/NIO模型        │
            │ 线程池参数        │MyBatis缓存       │
            │ Spring事务失效    │SpringBoot装配    │
            │ 缓存三大问题      │Kafka零拷贝       │
            ├──────────────────┼──────────────────┤
  基础必会   │ Java基础类型      │异常体系          │
            │ JVM内存结构       │注解原理          │
            │ Spring IOC/AOP   │网络TCP/HTTP      │
            │ MySQL索引B+树     │限流算法          │
            └──────────────────┴──────────────────┘

策略：
  高频+高难度 → 重点准备，能讲源码级
  高频+中难度 → 熟练掌握，不出错
  高频+基础   → 保证不丢分
  低频+高难度 → 了解即可，有余力再深入
```
