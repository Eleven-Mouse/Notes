## 二、核心知识点

### 2.1 CountDownLatch（倒计时门闩）

**核心**：一个线程等待其他 N 个线程执行完毕后再继续。

```
主线程 await()
    │
    ├── 阻塞等待 ──────────────────────────────┐
    │                                           │
    │   线程1 countDown()  count: 3 → 2        │
    │   线程2 countDown()  count: 2 → 1        │
    │   线程3 countDown()  count: 1 → 0        │
    │                                           │
    └── count==0，主线程被唤醒 ◄──────────────────┘
```

```java
// 经典场景：主线程等待所有子任务完成
CountDownLatch latch = new CountDownLatch(3);

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        try {
            // 执行子任务
            Thread.sleep(1000);
        } finally {
            latch.countDown(); // 计数 -1
        }
    }).start();
}

latch.await(5, TimeUnit.SECONDS); // 阻塞等待，最多等 5 秒
System.out.println("所有子任务完成，继续执行");
```

**要点**：
- countDown() 可以在任意线程调用多次，但 count 只减到 0
- await() 可以带超时参数
- **一次性**：count 归零后不可重置

### 2.2 CyclicBarrier（循环栅栏）

**核心**：N 个线程互相等待，全部到达屏障点后一起继续执行。

```
  线程1 ──→ await() ── 等待...
  线程2 ──→ await() ── 等待...
  线程3 ──→ await() ── 全部到达 → 执行屏障动作 → 全部继续
       ↓
  （可复用，下一轮又开始等待）
```

```java
// 经典场景：多线程分段计算，每段计算完后汇总
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程到达屏障点，执行汇总");
});

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        System.out.println(Thread.currentThread().getName() + " 计算中...");
        try {
            barrier.await(); // 等待其他线程
        } catch (Exception e) { }
        System.out.println(Thread.currentThread().getName() + " 继续执行");
    }).start();
}
```

**要点**：
- 所有线程都调用 await() 后才继续
- 可以指定 barrierAction（屏障触发时执行的回调）
- **可复用**：一轮结束后自动重置，进入下一轮（Cyclic 的含义）

---

### 2.3 CountDownLatch vs CyclicBarrier 详细对比

| 对比维度 | CountDownLatch | CyclicBarrier |
|---------|---------------|---------------|
| 核心语义 | 一个线程等 N 个线程 | N 个线程互相等 |
| 复用性 | 一次性，不可重置 | 可循环复用 |
| 计数方式 | countDown() 递减 | await() 计数到达 |
| 回调动作 | 无 | 支持 barrierAction |
| 异常处理 | 某线程异常不影响其他线程 | 某线程异常导致 BrokenBarrierException |
| 底层实现 | 基于 AQS（共享模式） | 基于 ReentrantLock + Condition |
| 适用场景 | 主线程等待子任务全部完成 | 多线程分阶段并行处理 |

**记忆口诀**：CountDownLatch = "裁判等运动员到终点"；CyclicBarrier = "几个朋友约好在路口集合再一起出发"。

### 2.4 Semaphore（信号量）

**核心**：控制同时访问共享资源的线程数量（限流）。

```java
// 经典场景：数据库连接池限制并发数
Semaphore semaphore = new Semaphore(5); // 最多 5 个线程同时访问

for (int i = 0; i < 20; i++) {
    new Thread(() -> {
        try {
            semaphore.acquire(); // 获取许可（P 操作）
            System.out.println("执行业务逻辑");
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            semaphore.release(); // 释放许可（V 操作）
        }
    }).start();
}
// 同一时间最多 5 个线程在执行，其他线程等待
```

**要点**：
- acquire() 获取许可，没有许可则阻塞
- release() 释放许可（注意：release 可以多于 acquire，增加许可数）
- 支持公平/非公平模式：`new Semaphore(5, true)`
- 常见用途：限流、资源池

---

### 2.5 Exchanger（交换器）

**核心**：两个线程在交换点交换数据。

```java
Exchanger<String> exchanger = new Exchanger<>();

// 线程A
new Thread(() -> {
    String dataA = "来自A的数据";
    String received = exchanger.exchange(dataA); // 交换
    System.out.println("A 收到: " + received);   // "来自B的数据"
}).start();

// 线程B
new Thread(() -> {
    String dataB = "来自B的数据";
    String received = exchanger.exchange(dataB); // 交换
    System.out.println("B 收到: " + received);   // "来自A的数据"
}).start();
```

**要点**：
- 只能用于两个线程之间
- exchange() 阻塞等待配对线程到达
- 适用场景：遗传算法（交叉配对）、数据校验（比对两份结果）

---

### 2.6 Phaser（阶段器，JDK7）

**核心**：更灵活的 CyclicBarrier，支持动态注册/注销参与者、多阶段执行。

```java
Phaser phaser = new Phaser(3); // 3 个参与者

// 阶段 0：所有线程到达后进入下一阶段
phaser.arriveAndAwaitAdvance();

// 动态增加参与者
phaser.register();

// 到达并注销自己（减少参与者）
phaser.arriveAndDeregister();

// 自定义每个阶段的行为
protected boolean onAdvance(int phase, int registeredParties) {
    // phase: 当前阶段编号
    // 返回 true 表示终止 Phaser
    return phase >= 3; // 执行 4 个阶段后终止
}
```

| 特性 | CyclicBarrier | Phaser |
|------|--------------|--------|
| 参与者数量 | 固定 | 动态注册/注销 |
| 阶段数 | 单一屏障 | 支持多阶段 |
| 回调 | barrierAction | onAdvance() |
| 灵活性 | 低 | 高 |

---

### 2.7 各工具类对比总结表

| 工具类 | 核心功能 | 是否可复用 | 基于 AQS | 典型场景 |
|--------|---------|-----------|---------|---------|
| CountDownLatch | 等N个线程完成 | 一次性 | 是 | 并行任务汇总 |
| CyclicBarrier | N线程互相等待 | 可复用 | 否 | 分阶段并行 |
| Semaphore | 控制并发数 | 持续使用 | 是 | 限流/资源池 |
| Exchanger | 两线程交换数据 | 可复用 | 否 | 数据交换/校验 |
| Phaser | 多阶段同步 | 可复用 | 否 | 复杂多阶段任务 |

### 2.8 实际使用场景

| 场景 | 推荐工具 |
|------|---------|
| 主线程等待多个微服务调用返回 | CountDownLatch |
| 模拟并发压测（N个线程同时开始） | CyclicBarrier |
| 接口限流（最多N个并发） | Semaphore |
| 多轮数据处理（每轮等所有人完成再开始下一轮） | CyclicBarrier / Phaser |

| 流水线式多阶段并行 | Phaser |

## 三、面试题

### Q1：CountDownLatch 和 CyclicBarrier 的区别？（高频）
**答**：(1) 语义不同：CountDownLatch 是一个线程等 N 个线程，CyclicBarrier 是 N 个线程互相等；(2) CountDownLatch 一次性不可复用，CyclicBarrier 可循环使用；(3) CyclicBarrier 支持屏障回调 barrierAction；(4) 底层不同：CountDownLatch 基于 AQS，CyclicBarrier 基于 Lock + Condition。

### Q2：Semaphore 有什么用？原理是什么？
**答**：Semaphore 控制同时访问资源的线程数量，用于限流。基于 AQS 共享模式，acquire() 获取许可（state-1），release() 释放许可（state+1）。支持公平/非公平模式。

### Q3：CountDownLatch 能不能重复使用？
**答**：不能。CountDownLatch 是一次性的，count 归零后无法重置。如果需要重复使用，应该用 CyclicBarrier。

### Q4：CyclicBarrier 的屏障回调是什么时候执行的？
**答**：最后一个到达屏障的线程执行 barrierAction 回调，回调执行完后所有等待线程才继续。注意：barrierAction 中不应做耗时操作。

### Q5：Semaphore 的 release() 不调用 acquire() 可以吗？
**答**：可以。release() 会增加许可数，即使没有调用过 acquire()。这可以用来动态增加许可数。但要注意如果不小心多 release 会导致实际并发数超出预期。

### Q6：Exchanger 了解吗？什么场景用？
**答**：Exchanger 用于两个线程在交换点交换数据。两个线程都调用 exchange() 时互相交换持有的数据。使用场景较少，典型如遗传算法中的基因交叉配对。

## 四、常见误区

| 误区 | 正确理解 |
|------|---------|
| "CountDownLatch 可以重置" | 一次性，不可重置，用 CyclicBarrier 替代 |
| "CyclicBarrier 某个线程异常不影响其他" | 会触发 BrokenBarrierException，其他线程也失败 |
| "Semaphore acquire 和 release 必须配对" | release 可以多于 acquire，会增加许可数 |
| "这些工具能替代 synchronized" | 工具类解决的是线程协作问题，不是互斥问题 |
| "CountDownLatch 必须在子线程 countDown" | 可以在任意线程调用，甚至可以在 await 的线程中 countDown |

## 五、实战场景

1. **并行任务汇总**：多线程查询不同数据源 → CountDownLatch 等所有结果返回 → 汇总
2. **并发压测**：CyclicBarrier 让所有线程同时开始请求
3. **接口限流**：Semaphore 控制最多 N 个请求同时处理
4. **多阶段任务**：Phaser 实现流水线式多轮并行计算
5. **批量导入**：CountDownLatch + 线程池，所有导入任务完成后通知前端
