## 二、核心知识点

### 2.1 访问修饰符

| 修饰符 | 同类 | 同包 | 子类 | 其他包 |
|--------|------|------|------|--------|
| private | ✅ | ❌ | ❌ | ❌ |
| default（无修饰） | ✅ | ✅ | ❌ | ❌ |
| protected | ✅ | ✅ | ✅ | ❌ |
| public | ✅ | ✅ | ✅ | ✅ |

### 2.2 重写（Override）vs 重载（Overload）

| 维度 | Override（重写） | Overload（重载） |
|------|-----------------|-----------------|
| 发生位置 | 子类与父类之间 | 同一个类中 |
| 方法签名 | 必须相同 | 必须不同（参数列表） |
| 返回类型 | 相同或协变返回 | 无限制 |
| 访问修饰符 | 不能更严格 | 无限制 |
| 异常 | 不能抛出更多受检异常 | 无限制 |
| 绑定时机 | 运行时（动态绑定） | 编译时（静态绑定） |

```java
// Override
class Animal { public void speak() {} }
class Dog extends Animal {
    @Override
    public void speak() { /* 汪汪 */ }  // 方法签名完全一致
}

// Overload
class Calculator {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }  // 参数不同
    public int add(int a, int b, int c) { return a + b + c; } // 参数不同
}
```

### 2.3 多态三要素

```
1. 有继承/实现关系
2. 有方法重写
3. 父类引用指向子类对象

Animal a = new Dog();  // 向上转型
a.speak();             // 运行时调用 Dog.speak()（动态绑定）
```

**多态的底层实现：虚方法表（vtable）**

```
JVM 为每个类维护一个虚方法表：
  - 存放该类所有虚方法的实际入口地址
  - 子类重写的方法会在子类的虚方法表中替换为子类实现
  - 运行时通过对象的实际类型找到虚方法表 → 确定调用哪个方法

invokevirtual 指令的实现过程：
  1. 找到操作数栈顶的对象引用
  2. 根据对象的实际类型（不是声明类型）查找虚方法表
  3. 调用实际类型中的方法实现
```

### 2.4 抽象类 vs 接口（2026 标准答案）

| 维度 | 抽象类 | 接口 |
|------|--------|------|
| 关键字 | abstract class | interface |
| 构造方法 | ✅ 可以有 | ❌ 不能有 |
| 成员变量 | 任意类型 | 只能 public static final |
| 方法实现 | 可以有具体方法 | JDK8: default/static; JDK9: private |
| 多继承 | 单继承 | 多实现 |
| 设计意图 | "是什么"（is-a） | "能做什么"（can-do） |
| this/super | ✅ | ❌（但 default 方法内可以用） |

```java
// 抽象类：模板方法模式
public abstract class AbstractParser {
    public final void parse(File file) {  // 模板方法（final 防止重写）
        byte[] data = readFile(file);     // 固定步骤
        Data result = doParse(data);      // 子类实现
        saveResult(result);               // 固定步骤
    }
    protected abstract Data doParse(byte[] data);  // 抽象方法
}

// 接口：行为契约
@FunctionalInterface
public interface Comparator<T> {
    int compare(T o1, T o2);           // 抽象方法
    default Comparator<T> reversed() { // default 方法
        return (o1, o2) -> compare(o2, o1);
    }
}
```

### 2.5 equals() 与 hashCode() 契约

```
规则 1：equals 相等 → hashCode 必须相等
规则 2：hashCode 相等 → equals 不一定相等（哈希冲突）
规则 3：重写 equals 必须同时重写 hashCode

违反后果：
  只重写 equals 不重写 hashCode → HashMap 中存入两个 "相等" 的对象
```

```java
// 正确写法
@Override
public boolean equals(Object o) {
    if (this == o) return true;           // 引用相同
    if (o == null || getClass() != o.getClass()) return false;
    User user = (User) o;
    return Objects.equals(name, user.name) && age == user.age;
}

@Override
public int hashCode() {
    return Objects.hash(name, age);       // 用相同字段计算 hash
}
```

### 2.6 深拷贝与浅拷贝

```java
// 浅拷贝：clone() 默认行为
class Address { String city; }
class User implements Cloneable {
    String name;
    Address address;

    @Override
    protected User clone() throws CloneNotSupportedException {
        return (User) super.clone();  // address 仍然是同一引用
    }
}

// 深拷贝：手动 clone 每个引用字段
@Override
protected User clone() throws CloneNotSupportedException {
    User copy = (User) super.clone();
    copy.address = address.clone();   // 递归 clone
    return copy;
}

// 更通用的深拷贝：序列化
public static <T> T deepCopy(T obj) {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    ObjectOutputStream oos = new ObjectOutputStream(bos);
    oos.writeObject(obj);
    ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
    ObjectInputStream ois = new ObjectInputStream(bis);
    return (T) ois.readObject();
}
```

## 三、面试题精选

### Q1：Java 是值传递还是引用传递？
```
Java 只有值传递。

基本类型：传递值的副本
引用类型：传递引用的副本（即地址值的副本）

示例：
  void swap(Student a, Student b) {
      Student temp = a;
      a = b;       // 只改了副本的指向
      b = temp;    // 外部不受影响
  }
  // swap(x, y) 后 x 和 y 的指向不变

但是：通过引用副本可以修改对象的内容
  void setName(Student s) { s.name = "new"; }  // 外部对象被修改了
```

### Q2：接口能继承接口吗？抽象类能实现接口吗？
```
接口可以继承接口（多继承）：interface A extends B, C {}
抽象类可以实现接口：abstract class D implements A {}
抽象类只能单继承：abstract class D extends BaseClass {}
```

### Q3：为什么重写 equals 必须重写 hashCode？
```
HashMap/HashSet 的存储逻辑：
  1. 先计算 hashCode → 定位桶
  2. 再用 equals 判断是否相同

如果只重写 equals：
  两个 equals 相等的对象 → 可能 hashCode 不同 → 分到不同桶
  → HashMap 认为是两个不同的 key → 数据错误

Object 的 hashCode 默认返回内存地址
```

### Q4：抽象类能实例化吗？
```
不能直接 new，但可以通过子类实例化：
  Animal a = new Dog();  // Dog 是具体子类

匿名内部类方式：
  Animal a = new Animal() {  // 创建匿名子类
      @Override public void speak() { ... }
  };
```

### Q5：多态的缺点是什么？
```
1. 不能调用子类特有的方法（需要向下转型）
2. 向下转型不安全（可能 ClassCastException）
3. 解决：先 instanceof 判断
   if (a instanceof Dog dog) { dog.fetch(); }  // JDK16 模式匹配
```
