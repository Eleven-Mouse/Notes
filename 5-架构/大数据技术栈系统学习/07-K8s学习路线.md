# K8s 学习路线：从小白到架构思维

## 结论

K8s，也就是 Kubernetes，是容器编排平台。它的核心价值是：**在一组机器上自动部署、调度、扩缩容和管理容器化应用。**

它不是大数据计算框架，也不是数据库。它是应用和基础组件的运行底座。

## 它是什么

先理解 Docker：

```text
代码 -> 镜像 -> 容器
```

再理解 K8s：

```text
多个容器
  |
  v
多个 Pod
  |
  v
多个 Node
  |
  v
一个 K8s 集群统一调度和管理
```

K8s 帮你解决：

- 服务部署到哪台机器。
- 服务挂了怎么拉起来。
- 服务怎么扩容。
- 服务之间怎么访问。
- 配置怎么管理。
- 密钥怎么管理。
- 存储怎么挂载。
- 流量怎么进入集群。

## 什么时候用

适合用 K8s：

- 服务数量多。
- 需要统一部署管理。
- 需要弹性扩缩容。
- 需要滚动发布。
- 需要服务发现。
- 需要资源隔离。
- 需要混合部署 Java 服务、网关、任务、组件。
- 团队有一定运维能力。

不适合过早使用：

- 只有一个很小的服务。
- 单机部署足够。
- 团队还不懂 Docker。
- 没有监控、日志、排障基础。
- 引入后没人维护。

架构判断：

```text
K8s 适合治理“很多服务怎么稳定运行”，不适合拿来掩盖系统设计混乱。
```

## 能做什么

K8s 可以：

- 部署 Java 后端服务。
- 部署网关。
- 部署定时任务。
- 部署管理后台。
- 部署 Spark Operator。
- 部署 Doris、Kafka、Redis 等组件。
- 做滚动发布。
- 做副本扩容。
- 做健康检查。
- 做配置和密钥管理。

典型链路：

```text
Jenkins 构建 Docker 镜像
  |
  v
推送镜像仓库
  |
  v
K8s 拉取镜像
  |
  v
创建 Pod
  |
  v
Service 暴露服务
```

## 架构位置

K8s 位于运行平台层：

```text
应用代码
  |
  v
Docker 镜像
  |
  v
K8s 集群
  |
  v
Pod / Service / Ingress / Volume
```

在大数据体系中：

```text
Spark：数据计算
Doris：数据查询
Jenkins：自动化流水线
K8s：运行和调度平台
```

## 重点难点

### Pod

Pod 是 K8s 的最小调度单位。

一个 Pod 里可以有一个或多个容器。

大多数业务场景：

```text
一个 Pod 一个主业务容器
```

特殊场景可能有 Sidecar，比如日志代理、服务网格代理。

### Service

Pod 会重建，IP 会变。

Service 解决：

```text
怎么稳定访问一组 Pod？
```

它提供固定访问入口，并把流量转发到后端 Pod。

### Deployment 和 StatefulSet

Deployment 适合无状态服务：

- Java API
- Web 服务
- 普通后台服务

StatefulSet 适合有状态服务：

- 数据库
- Doris BE
- Kafka
- ZooKeeper

架构判断：

```text
能无状态就无状态，必须有状态才用 StatefulSet 或 Operator。
```

### 健康检查

Liveness Probe：

```text
服务是不是活着，不活就重启。
```

Readiness Probe：

```text
服务是否准备好接流量，没准备好就先不转发请求。
```

这两个混乱配置，会导致服务频繁重启或流量打到未就绪实例。

```text

  |
  v

  |
  v

  |
  v

  |
  v

```

进阶版：

```text
Spark 任务 Jar
  |

镜像化
  |
  v

```

验收标准：

- 能写 Deployment YAML。
- 能创建 Service。
- 能查看 Pod 日志。
- 能滚动更新镜像版本。
- 能通过 ConfigMap 修改配置。
- 能解释 Pod 重启原因。

## 一句话总结

K8s 的核心是：**把容器化服务放到集群里稳定运行，并提供部署、扩容、服务发现、配置、存储和故障恢复能力。**
