# 以博客项目为主的大数据技术栈系统学习路线

## 结论

Doris、Scala、Spark、HDFS、Jenkins、K8s、分布式这些内容，整体属于**大数据 / 数据平台 / 分布式系统 / 平台工程**技术栈。

对你来说，最合适的学习方式不是单独搭一堆空组件，而是以博客项目为主线，把它逐步升级成：

```text
博客系统 + 自动化部署平台 + 访问日志分析平台
```

不要把它们当成一堆孤立名词学。更合理的理解方式是：

```text
博客访问日志 -> HDFS 存储 -> Spark + Scala 清洗计算 -> Doris 查询分析 -> Jenkins 自动化 -> K8s 部署与资源编排
```

其中：

- **HDFS** 负责存大数据。
- **Spark** 负责算大数据。
- **Scala** 是写 Spark 任务常用的语言之一。
- **Doris** 负责让数据能被快速查询和分析。
- **Jenkins** 负责自动化构建、测试、部署和调度。
- **K8s / Kubernetes** 负责容器编排、服务部署、弹性伸缩和资源调度。
- **分布式** 是这些系统背后的基础思想。

在博客项目里的对应关系：

| 技术 | 博客项目里的落点 |
| --- | --- |
| Jenkins | 自动构建博客、运行测试、打包镜像、触发部署 |
| K8s | 部署博客服务、滚动更新、健康检查、配置管理 |
| HDFS | 保存博客访问日志和历史行为数据 |
| Scala | 编写 Spark 日志清洗和聚合任务 |
| Spark | 统计 PV、UV、热门文章、访问来源、慢请求 |
| Doris | 保存统计结果，支撑后台报表和 SQL 分析 |
| 分布式 | 多实例、高可用、日志链路、数据存储和计算的底层思维 |

## 这些技术分别是什么

| 技术 | 类型 | 解决的问题 |
| --- | --- | --- |
| 分布式 | 系统设计思想 | 多台机器一起工作，解决单机存不下、算不动、扛不住的问题 |
| HDFS | 分布式文件系统 | 把大文件切块，分散存储到多台机器上 |
| Spark | 分布式计算引擎 | 对海量数据做清洗、转换、聚合、分析 |
| Scala | JVM 编程语言 | 常用于编写 Spark 任务，语法简洁，函数式能力强 |
| Doris | 实时分析型数据库 / OLAP 数仓 | 面向报表、BI、实时查询和聚合分析 |
| Jenkins | 自动化工具 | 自动拉代码、编译、测试、打包、部署 |
| K8s / Kubernetes | 容器编排平台 | 管理容器化应用的部署、扩缩容、服务发现和资源调度 |

说明：`jerkins` 通常应写作 **Jenkins**。
说明：`K8s` 是 **Kubernetes** 的常见缩写，`8` 代表中间省略了 8 个字母。

## 它们之间的关系

可以把这套体系理解成一个“数据工厂”：

```text
业务系统 / 日志 / 数据库
        |
        v
    数据采集
        |
        v
      HDFS
  存放原始大数据
        |
        v
      Spark
  清洗、转换、聚合
        |
        v
      Doris
  面向查询和报表分析
        |
        v
  BI 报表 / 数据接口 / 业务分析
```

Jenkins 不直接处理数据，它更像自动化流水线：

```text
提交代码 -> Jenkins 拉代码 -> 编译测试 -> 打包 -> 部署或触发数据任务
```

K8s 也不直接处理数据，它更像应用和任务的运行底座：

```text
镜像 -> Pod -> Service -> Deployment / StatefulSet -> 集群调度与运行
```

简单说：

```text
Jenkins：负责把代码构建和发布出去
K8s：负责让服务或任务稳定跑在集群里
```

## 学习顺序

### 第一阶段：基础能力

先补这些基础，不然后面会学得很散：

- Linux 常用命令
- SQL 基础和进阶
- Java 基础
- Git 基础
- Maven 或 Gradle 基础

重点不是“学完所有基础”，而是达到能看懂项目、能跑命令、能查日志、能写 SQL 的程度。

### 第二阶段：分布式基础

先理解这些概念：

- 为什么需要分布式
- 分片
- 副本
- 主从架构
- 容错
- 重试
- 幂等
- 一致性
- CAP
- 数据倾斜

这一阶段的目标不是背概念，而是能回答：

> 为什么一台机器不够用？多台机器一起工作会引入哪些新问题？

### 第三阶段：HDFS

重点学习：

- NameNode
- DataNode
- Block
- 副本机制
- 文件上传和下载
- HDFS 权限
- 小文件问题

常用命令：

```bash
hdfs dfs -ls /
hdfs dfs -put local.txt /tmp/
hdfs dfs -cat /tmp/local.txt
hdfs dfs -get /tmp/local.txt ./
```

这一阶段的目标：

- 能把文件上传到 HDFS。
- 能从 HDFS 读取文件。
- 能解释 HDFS 为什么适合存大文件。
- 能说清楚 NameNode 和 DataNode 的职责。

### 第四阶段：Scala + Spark

Scala 不需要一开始学得特别深，先学 Spark 够用的部分：

- 变量和函数
- 集合操作
- case class
- 模式匹配
- Option
- map / flatMap / filter / reduce

Spark 重点学习：

- RDD
- DataFrame
- Dataset
- Spark SQL
- Transformation 和 Action
- Shuffle
- Partition
- Cache
- Join 优化
- 数据倾斜处理

这一阶段的目标：

- 能从 HDFS 读取数据。
- 能用 Spark 清洗和转换数据。
- 能按天、用户、类型等维度做聚合。
- 能把处理结果写出到文件或 Doris。

### 第五阶段：Doris

Doris 偏向查询和分析，不是用来替代 Spark 做复杂离线计算的。

重点学习：

- OLAP 是什么
- Doris 的 FE 和 BE
- Duplicate Key 表
- Aggregate Key 表
- Unique Key 表
- 分区
- 分桶
- 数据导入
- SQL 查询
- 物化视图
- 查询优化

这一阶段的目标：

- 能创建 Doris 表。
- 能把 Spark 处理后的结果导入 Doris。
- 能写 SQL 做报表查询。
- 能理解分区和分桶为什么会影响查询性能。

### 第六阶段：Jenkins

Jenkins 重点不是界面操作，而是自动化流水线思想。

重点学习：

- Job
- Pipeline
- Jenkinsfile
- 参数化构建
- 定时构建
- 凭据管理
- 拉取 Git 代码
- 编译 Maven 项目
- 执行测试
- 打包部署

一个典型 Pipeline：

```text
拉取代码 -> 编译 -> 测试 -> 打包 -> 上传产物 -> 部署或触发任务
```

这一阶段的目标：

- 能写一个简单 Jenkinsfile。
- 能自动构建 Java 或 Spark 项目。
- 能定时触发一个数据处理任务。

### 第七阶段：K8s / Kubernetes

K8s 的重点是理解“容器化应用如何在集群里运行”。

先学 Docker，再学 K8s 会更顺：

- 镜像
- 容器
- Dockerfile
- 镜像仓库

K8s 重点学习：

- Pod
- Node
- Namespace
- Deployment
- StatefulSet
- DaemonSet
- Service
- Ingress
- ConfigMap
- Secret
- Volume
- PVC
- Helm
- 资源限制：CPU、Memory
- 健康检查：Liveness Probe、Readiness Probe

这一阶段的目标：

- 能把一个 Java 服务打成 Docker 镜像。
- 能把服务部署到 K8s。
- 能通过 Service 访问服务。
- 能查看 Pod 日志和状态。
- 能理解 Deployment 和 StatefulSet 的区别。
- 能理解为什么 Doris、Kafka、数据库这类有状态服务上 K8s 会更复杂。

## 最小实战项目

建议做一个“小型用户访问日志分析平台”。

### 项目目标

把一份用户访问日志，从原始文件处理成可查询的统计结果。

### 数据样例

```text
user_id,page,event_time,event_type
1001,/home,2026-07-01 10:00:00,view
1002,/product,2026-07-01 10:01:00,click
1001,/cart,2026-07-01 10:03:00,click
```

### 处理链路

```text
CSV 日志文件
    |
    v
上传到 HDFS
    |
    v
Spark 读取并清洗
    |
    v
按天统计 PV / UV / 点击数
    |
    v
写入 Doris
    |
    v
SQL 查询分析
    |
    v
Jenkins 定时触发任务
    |
    v
可选：部署到 K8s 运行
```

### 项目验收标准

- 能把 CSV 上传到 HDFS。
- Spark 能读取 HDFS 上的数据。
- Spark 能过滤脏数据。
- Spark 能统计每天的 PV、UV、点击数。
- Doris 能保存统计结果。
- Doris SQL 能查出日报数据。
- Jenkins 能自动触发构建或任务执行。
- 可选：K8s 能运行一个查询服务、调度服务或数据处理任务。

## 学习重点排序

如果目标是 Java 后端或大数据开发，建议优先级如下：

```text
SQL > Java > Linux > Spark > HDFS > Doris > Docker > Jenkins > K8s > 分布式原理深入
```

原因：

- SQL 是数据开发和后端开发都绕不开的基础。
- Java 是大多数企业后端和大数据组件生态的基础。
- Linux 是部署、排查、运行任务的基本功。
- Spark 是大数据计算的核心。
- HDFS 是理解大数据存储的入口。
- Doris 是偏实时分析和数仓查询的能力。
- Docker 是现代部署的基础。
- Jenkins 是工程化和自动化能力。
- K8s 是容器编排和资源调度能力。
- 分布式原理要持续学习，但不建议一开始陷进理论细节。

## 常见误区

### 误区一：一开始就啃源码

源码可以看，但不要一开始就看。先会用，再理解原理，最后再看源码。

### 误区二：只背概念，不做项目

比如只知道 “Spark 有 Shuffle”，但不知道什么时候会发生 Shuffle，也不知道怎么排查慢任务，这样面试和工作都不够用。

### 误区三：把 Doris 和 Spark 混为一谈

Spark 更偏计算，Doris 更偏查询分析。

简单说：

```text
Spark：把数据算出来
Doris：让数据查得快
```

### 误区四：忽略 Linux 和 SQL

很多人一上来学框架，结果连日志不会查、SQL 写不稳。大数据开发里，Linux 和 SQL 是底座。

### 误区五：把 K8s 当成大数据计算框架

K8s 不是 Spark，也不是 Doris。

简单说：

```text
Spark：负责计算
Doris：负责查询分析
K8s：负责把服务、任务和组件调度起来运行
```

K8s 能运行 Spark、Doris、Flink、Kafka 等组件，但它本身不是用来写数据计算逻辑的。

## 一句话总结

先把这条链路跑通：

```text
HDFS 存数据 -> Spark 算数据 -> Doris 查数据 -> Jenkins 自动化 -> K8s 管运行
```

跑通之后，再回头补分布式原理和性能优化。这样不会学成“名词收藏家”，而是能真正做出东西。
