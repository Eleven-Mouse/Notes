# 大数据与平台技术栈系统学习总览

## 结论

这套技术不要按“名词列表”学，要按架构链路学：

```text
分布式思想
  -> HDFS 存数据
  -> Scala 写计算逻辑
  -> Spark 算数据
  -> Doris 查数据
  -> Jenkins 做自动化
  -> K8s 管运行
```

对应到系统分层：

| 层次 | 技术 | 核心作用 |
| --- | --- | --- |
| 底层思想 | 分布式 | 解释为什么多机器系统会复杂 |
| 存储层 | HDFS | 存海量大文件 |
| 开发语言 | Scala | 编写 Spark 数据处理逻辑 |
| 计算层 | Spark | 清洗、转换、聚合、Join |
| 分析层 | Doris | 快速 SQL 查询、报表和 BI |
| 自动化层 | Jenkins | 构建、测试、打包、部署 |
| 运行平台层 | K8s | 容器编排、资源调度、服务治理 |

## 一条完整链路

```text
业务系统产生日志
  |
  v
日志上传到 HDFS
  |
  v
Spark 读取 HDFS 数据
  |
  v
Scala 编写清洗和聚合逻辑
  |
  v
结果写入 Doris
  |
  v
BI 或报表查询 Doris
  |
  v
Jenkins 自动构建和触发任务
  |
  v
K8s 运行服务、任务或相关组件
```

## 学习重点

新手最容易犯的错误是每个组件都学一点，但不知道它们为什么出现、分别站在哪一层。

你应该优先抓住这些问题：

- 什么时候单机不够，必须分布式？
- 数据为什么要放 HDFS，而不是直接放 MySQL？
- Spark 为什么适合做 ETL，而不适合做在线接口？
- Scala 在 Spark 里扮演什么角色？
- Doris 为什么适合报表查询，而不是替代 Spark？
- Jenkins 解决的是自动化问题，不是运行平台问题。
- K8s 解决的是容器编排问题，不是数据计算问题。

## 最小实战目标

做一个用户访问日志分析项目：

```text
access.log
  -> HDFS
  -> Spark + Scala
  -> Doris
  -> Jenkins 自动触发
  -> 可选：K8s 运行服务或任务
```

验收标准：

- 能解释每个组件为什么出现。
- 能把数据从 HDFS 读出来。
- 能用 Spark 处理数据。
- 能把结果写入 Doris。
- 能用 SQL 查出报表结果。
- 能用 Jenkins 自动构建或触发。
- 能理解 K8s 在部署和运行层的作用。
