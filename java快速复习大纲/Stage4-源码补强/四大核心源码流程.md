## 1. Spring IOC 启动流程 ⭐🔥

### 核心入口：AnnotationConfigApplicationContext

```
new AnnotationConfigApplicationContext(AppConfig.class)
    │
    ├── 1. this() → 创建 DefaultListableBeanFactory
    │   ├── 注册内置后置处理器（ConfigurationClassPostProcessor等）
    │   └── AnnotatedBeanDefinitionReader + ClassPathBeanDefinitionScanner
    │
    ├── 2. register(configClass) → 将配置类注册为BeanDefinition
    │
    └── 3. refresh() → 核心方法（12步）
        │
        ├── ① prepareRefresh()           → 准备工作，记录启动时间
        ├── ② obtainFreshBeanFactory()   → 获取/创建BeanFactory
        ├── ③ prepareBeanFactory()       → 配置BeanFactory的标准特性
        ├── ④ postProcessBeanFactory()   → 子类重写的钩子
        │
        ├── ⑤ invokeBeanFactoryPostProcessors()  ← 重要！
        │   ├── 执行 BeanDefinitionRegistryPostProcessor
        │   │   └── ConfigurationClassPostProcessor
        │   │       ├── 解析 @ComponentScan → 扫描包下所有@Component/@Service/@Repository
        │   │       ├── 解析 @Import → 导入配置
        │   │       ├── 解析 @Bean → 注册为BeanDefinition
        │   │       └── 解析 @PropertySource → 加载配置文件
        │   └── 执行 BeanFactoryPostProcessor
        │       └── PropertyPlaceholderConfigurer → 替换 ${}
        │
        ├── ⑥ registerBeanPostProcessors()  → 注册BeanPostProcessor实现类
        ├── ⑦ initMessageSource()           → 国际化
        ├── ⑧ initApplicationEventMulticaster() → 事件发布器
        ├── ⑨ onRefresh()                   → 子类扩展（如Servlet容器）
        ├── ⑩ registerListeners()           → 注册监听器
        │
        ├── ⑪ finishBeanFactoryInitialization()  ← 重要！实例化所有非懒加载单例Bean
        │   └── beanFactory.preInstantiateSingletons()
        │       └── getBean() → doGetBean()
        │           ├── 先查单例缓存（三级缓存解决循环依赖）
        │           ├── 没有则创建：createBean() → doCreateBean()
        │           │   ├── createBeanInstance()  → 反射实例化
        │           │   ├── populateBean()        → 属性注入
        │           │   └── initializeBean()      → 初始化（BeanPostProcessor）
        │           └── 放入单例池 singletonObjects
        │
        └── ⑫ finishRefresh() → 发布ContextRefreshedEvent
```

### 面试表述（30秒版）

> "Spring IOC启动的核心在refresh()方法，分12步。最重要的是第5步invokeBeanFactoryPostProcessors，扫描@Component/@Service等注解注册BeanDefinition。然后第11步finishBeanFactoryInitialization实例化所有非懒加载单例Bean。创建Bean时走三阶段：实例化（反射调构造方法）→属性注入（@Autowired）→初始化（BeanPostProcessor，AOP代理在此生成）。循环依赖通过三级缓存解决。"

## 2. Spring AOP 代理创建流程 ⭐🔥

### 代理对象何时创建？

```
在 BeanPostProcessor.postProcessAfterInitialization() 中创建

AbstractAutoProxyCreator.postProcessAfterInitialization()
    │
    ├── wrapIfNecessary(bean, beanName, cacheKey)
    │   ├── 1. getAdvicesAndAdvisorsForBean() → 找匹配的切面
    │   │   ├── 找所有 @Aspect 标注的类
    │   │   ├── 解析切点表达式 @Pointcut
    │   │   └── 检查当前Bean是否匹配
    │   │
    │   ├── 2. createProxy() → 创建代理
    │   │   ├── 如果有接口 → JdkDynamicAopProxy
    │   │   │   └── Proxy.newProxyInstance(classLoader, interfaces, invocationHandler)
    │   │   └── 如果无接口 → CglibAopProxy
    │   │       └── Enhancer.create(targetClass, MethodInterceptor)
    │   │
    │   └── 返回代理对象（替换原始Bean）
    │
    └── 代理对象的方法调用链
        ├── JdkDynamicAopProxy.invoke()
        │   └── ReflectiveMethodInvocation.proceed()
        │       ├── 切面1.before()
        │       ├── 切面2.around() → proceed()
        │       │   ├── 目标方法执行
        │       │   └── 切面2.around()返回
        │       └── 切面1.after()
        │
        └── 责任链模式：MethodInvocation持有拦截器链，依次执行
```

### 面试表述

> "AOP代理在Bean初始化阶段由BeanPostProcessor创建。AbstractAutoProxyCreator扫描@Aspect注解的类，解析切点表达式，匹配当前Bean。有接口用JDK动态代理（Proxy.newProxyInstance），无接口用CGLIB（生成子类）。方法调用时走责任链模式，ReflectiveMethodInvocation依次执行@Before/@Around/@After等通知，最后执行目标方法。"

## 3. MyBatis 执行流程 ⭐🔥

### 从 Mapper 接口到 SQL 执行

```
articleMapper.selectById(1L)
    │
    ├── 1. MapperProxy.invoke()  ← 动态代理入口
    │   └── MyBatis在Spring启动时为每个Mapper接口创建了代理对象
    │
    ├── 2. MapperMethod.execute()
    │   └── 根据SQL类型分发：SELECT/INSERT/UPDATE/DELETE
    │
    ├── 3. SqlSession.selectOne()
    │   └── Configuration.getMappedStatement("ArticleMapper.selectById")
    │       → 获取MappedStatement（封装SQL语句、参数映射、结果映射）
    │
    ├── 4. Executor.query()
    │   ├── SimpleExecutor（默认）
    │   ├── 先查二级缓存（namespace级别）
    │   ├── 再查一级缓存（SqlSession级别，LocalCache）
    │   └── 都没有 → queryFromDatabase()
    │
    ├── 5. StatementHandler.prepare() → 创建Statement
    │   └── ParameterHandler.setParameters() → 设置参数
    │       └── 用 #{} → PreparedStatement.setParameter()（防注入）
    │       用 ${} → 直接拼接SQL（有注入风险！）
    │
    ├── 6. ResultSetHandler.handleResultSets() → 结果映射
    │   ├── resultMap映射（列名→字段）
    │   ├── 嵌套查询（N+1问题）
    │   └── 延迟加载（lazyLoadingEnabled）
    │
    └── 7. 写入一级缓存 → 返回结果

一级缓存 vs 二级缓存：
  一级缓存：SqlSession级别，默认开启，不能关闭
    同一个SqlSession内，相同SQL+参数 → 直接返回缓存
    执行INSERT/UPDATE/DELETE → 清空该SqlSession缓存
  二级缓存：namespace级别，需手动开启
    多个SqlSession共享
    脏数据风险：关联表更新时，缓存可能过期
    生产中一般不用MyBatis二级缓存，用Redis代替
```

### 面试表述

> "MyBatis为Mapper接口创建动态代理（MapperProxy）。调用方法时走：MapperProxy→MapperMethod→SqlSession→Executor→StatementHandler。Executor先查缓存（二级→一级），没有则执行SQL。ParameterHandler用#{}生成PreparedStatement参数（防注入），${}直接拼接有注入风险。ResultSetHandler做结果映射，嵌套查询可能产生N+1问题。一级缓存SqlSession级别默认开启，二级缓存namespace级别一般不用，用Redis替代。"

## 4. ConcurrentHashMap（JDK8）原理 ⭐🔥

### 数据结构

```
JDK7：Segment[] + HashEntry[]（分段锁，16个Segment）
JDK8：Node[] + 链表/红黑树（CAS + synchronized，锁粒度更细）

JDK8 结构：
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │...│15 │  ← Node数组（默认16）
└─┬─┴───┴─┬─┴───┴───┴───┴───┴───┘
  │       │
  ▼       ▼
 Node    Node → Node → Node → Node (链表)
          │
          └→ 当链表长度>=8 且数组长度>=64 → 转红黑树
              TreeNode（红黑树，O(logN)查找）
```

### put 流程（核心源码逻辑）

```
put(key, value)
  │
  ├── 1. 计算hash = spread(key.hashCode())
  │
  ├── 2. 判断table是否为空 → initTable()（CAS初始化）
  │
  ├── 3. 定位桶 index = (n-1) & hash
  │   ├── 桶为空 → CAS插入新Node（无锁！）
  │   │   └── compareAndSwapInt(tab, offset, null, newNode)
  │   │
  │   ├── 桶不为空 && hash == MOVED(-1) → helpTransfer()（协助扩容）
  │   │
  │   └── 桶不为空（hash冲突）
  │       ├── synchronized(头节点)  ← 只锁这一个桶！
  │       │   ├── 遍历链表，key相同 → 覆盖value
  │       │   ├── 没找到 → 尾插新Node
  │       │   └── 如果是TreeBin → 红黑树插入
  │       │
  │       └── 检查是否需要转红黑树（链表>=8 && 数组>=64）
  │
  ├── 4. addCount(1L) → 更新元素计数
  │   └── 检查是否需要扩容
  │
  └── 5. return 旧值或null

关键设计：
  1. 空桶用CAS插入（无锁，最快路径）
  2. 非空桶用synchronized锁头节点（锁粒度=单个桶）
  3. 锁升级从CAS到synchronized，比JDK7的Segment分段锁粒度更细
  4. 扩容时用transferIndex分片迁移，多线程协作扩容
```

### get 流程

```
get(key)
  │
  ├── 1. 计算hash
  ├── 2. 定位桶 (n-1) & hash
  ├── 3. 桶为空 → return null
  ├── 4. 头节点匹配 → return value
  ├── 5. 遍历链表/红黑树查找
  └── 注意：Node的val和next都是volatile → 保证可见性，get不需要加锁！
```

### 面试表述

> "ConcurrentHashMap JDK8用Node数组+链表+红黑树。put时空桶CAS插入无锁，冲突时synchronized锁头节点，锁粒度是单个桶比JDK7的Segment更细。get全程无锁，Node的val和next是volatile保证可见性。扩容时多线程协作，每个线程负责一段桶的迁移。链表长度>=8且数组>=64转红黑树。对比JDK7：JDK7用Segment分段锁（16段），JDK8用CAS+synchronized（锁粒度=桶），并发度从16提升到数组长度。"

## 5. HashMap（JDK8）put 流程 ⭐

```
put(key, value)
  │
  ├── 1. hash = key.hashCode() ^ (key.hashCode() >>> 16)  ← 扰动函数
  │      减少hash冲突：高16位异或低16位
  │
  ├── 2. table为空 → resize() 初始化（默认16）
  │
  ├── 3. index = (n-1) & hash  ← 等效于hash%n（n是2的幂）
  │   ├── 桶为空 → 直接插入
  │   ├── 桶不空 && key相同（equals）→ 覆盖value
  │   ├── 桶不空 && 是TreeNode → 红黑树插入
  │   └── 桶不空 && 是链表 → 尾插遍历
  │       ├── 找到相同key → 覆盖
  │       └── 没找到 → 尾插新Node
  │           └── 链表长度>=8
  │               ├── 数组长度<64 → resize()扩容（不转树）
  │               └── 数组长度>=64 → treeifyBin()转红黑树
  │
  ├── 4. ++size > threshold → resize()扩容
  │      threshold = capacity * loadFactor（默认16*0.75=12）
  │
  └── 扩容机制（2倍）
      ├── 创建新数组（2倍大小）
      ├── 重新计算每个元素的位置
      │   hash & oldCap == 0 → 原位置
      │   hash & oldCap != 0 → 原位置 + oldCap
      └── JDK8优化：不需要重新hash，用位运算判断

HashMap线程不安全：
  JDK7：并发put可能死循环（头插法+扩容形成环）
  JDK8：并发put可能数据丢失（两个线程同时CAS到同一个桶）
```

### 面试表述

> "HashMap底层Node数组+链表+红黑树。put先hash扰动减少冲突，定位桶用(n-1)&hash等效取模。空桶直接插入，冲突时链表尾插，链表>=8且数组>=64转红黑树。扩容2倍，JDK8优化用hash&oldCap判断新位置。线程不安全：JDK7头插法并发扩容会死循环，JDK8改尾插不会死循环但会数据丢失。多线程用ConcurrentHashMap。"
