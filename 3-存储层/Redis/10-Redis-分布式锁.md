>Redis 分布式锁的本质，是用低成本互斥解决多实例并发冲突，但必须配合幂等、超时、原子解锁和一致性兜底。


  - 基础层
      - 目标：多实例并发下，对同一资源做互斥。
      - 核心命令：SET key value NX PX ttl
      - 解锁原则：只能删“自己加的锁”。
  - 必会层
      - value 必须唯一，用来防误删。
      - ttl 必须有，防死锁。
      - 解锁要原子校验，通常用 Lua。
      - 不能用裸 SETNX + EXPIRE。
      - 不能用裸 DEL。
  - 风险层
      - Redis 主从是异步复制，故障切换可能双持锁。
      - GC 停顿、网络抖动、时钟漂移都可能破坏锁语义。
      - 锁过期不等于业务完成。
      - 锁只能降冲突，不能单独保证最终正确性。
  - Java 实战层
      - 常用：Redisson RLock
      - 重点参数：waitTime、leaseTime
      - 长任务：watchdog 续租
      - 热点场景：加幂等键、退避重试、监控等待时长
  - 高级层
      - 高风险场景要加 fencing token。
      - 最终正确性靠数据库唯一约束/版本号兜底。
      - Redlock 只适合“了解”，别把它当万能答案。
      - 锁粒度要细到资源 ID，不要全局大锁。
