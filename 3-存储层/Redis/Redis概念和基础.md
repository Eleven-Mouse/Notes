## Redis 概念

Redis（Remote Dictionary Server）是一个开源的**内存数据结构存储系统**，常被归类为 NoSQL。  
它支持字符串（String）、哈希（Hash）、列表（List）、集合（Set）、有序集合（ZSet）、流（Stream）等多种数据结构。  
Redis 主要用 C 语言开发，典型特点是：**快、功能多、可持久化**。

一句话理解：Redis 像一个“反应超快的内存仓库管理员”，你问它要数据，它通常比数据库先把答案甩你脸上。

---

## Redis 的典型使用场景

### 1. 缓存
把热点数据放到 Redis，减少 MySQL/PG 等数据库压力，降低响应时间。  
常见模式：旁路缓存（Cache Aside）。

### 2. 消息队列
- `List`：可实现简单队列（如 `LPUSH` + `RPOP`）。
- `Stream`：支持消费组、消息确认，更适合复杂消息场景。

### 3. 分布式锁
常见做法是 `SET key value NX EX seconds`（而不只是 `SETNX`）。  
`NX` 保证“只在 key 不存在时设置”，`EX` 设置过期时间，防止锁忘记释放。

### 4. 限时业务
使用 `EXPIRE` / `SETEX` / `SET ... EX` 实现“自动过期”能力。  
如：验证码 5 分钟失效、登录状态 30 分钟过期。

### 5. 限流
常见方案：Redis + Lua 脚本（保证原子性），实现固定窗口、滑动窗口、令牌桶等限流策略。

## Redis 为什么快？

1. **基于内存**：内存访问速度远高于磁盘。
2. **高效事件模型**：采用 I/O 多路复用，减少线程切换开销。
3. **命令执行模型简单**：核心命令处理流程单线程，避免大量锁竞争。
4. **数据结构优化**：针对不同场景设计了高效编码与结构。
5. **通信协议轻量**：RESP 协议简单，解析成本低。

补充：从 Redis 6 开始可选 I/O 线程用于网络读写，但命令执行主流程仍以单线程模型为核心。

---

## 为什么用 Redis

1. **性能高**：高并发读写能力强，适合低延迟场景。
2. **数据结构丰富**：不只 `key-value`，还能覆盖排行榜、去重、队列等需求。
3. **原子操作支持好**：如 `INCR`、`HINCRBY`、Lua 脚本等。
4. **支持持久化**：RDB、AOF，兼顾性能与数据可靠性。
5. **发布订阅能力**：支持 Pub/Sub；也可用 Stream 做更可靠的消息处理。
6. **易于分布式扩展**：支持主从复制、哨兵（Sentinel）、集群（Cluster）。

## Key / DB / TTL

### Key（键）
- Redis 的 key 是二进制安全字符串，建议使用有业务语义的命名。
- 推荐命名风格：`业务:模块:唯一标识`，例如：`user:profile:1001`。
- 注意控制 key 长度和数量，避免“键名比值还大”的尴尬。

### DB（逻辑库）
- Redis 默认有多个逻辑库（常见默认 16 个，编号 0~15），可通过 `SELECT` 切换。
- 在生产环境中，很多团队更倾向“一个实例一个业务/环境”，而不是依赖多 DB 隔离。

### TTL（生存时间）
- `TTL key`：查看剩余过期时间（秒）。
- `PTTL key`：毫秒级过期时间。
- `EXPIRE key seconds`：设置过期时间。
- `PERSIST key`：移除过期时间。
- 返回值常见含义：
  - `-2`：key 不存在
  - `-1`：key 存在但未设置过期时间

小提醒：没有 TTL 的缓存，严格来说不叫缓存，叫“常驻嘉宾”。

## 常用客户端

按语言看常用选择：

- Java：`Lettuce`（Spring Data Redis 默认常用）、`Redisson`（分布式锁与高级功能丰富）
- Python：`redis-py`
- Node.js：`ioredis`、`node-redis`
- Go：`go-redis`
- .NET：`StackExchange.Redis`

选型建议：
1. 先看生态和社区活跃度。
2. 再看是否需要连接池、集群、自动重连、序列化等能力。
3. 能用成熟客户端就别自己“手搓协议”，除非你准备把自己也优化成 Redis。
