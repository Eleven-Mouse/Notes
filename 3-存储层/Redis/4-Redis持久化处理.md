
> redis提供持久化处理机制：RDB快照和AOF日志

## RDB快照

>RDB快照总结就是一句话，在某一瞬间，将缓存中的数据“照”下来，写入磁盘，

### 一，redis提供了两种命令：

 1，save：save命令是在当前程序执行，生成RDB快照文件，由于和操作命令的执行和生成RDB文件是在同一个线程，如果消耗的时间太长，**会阻塞主线程**。
 2，bgsave：执行这个命令，redis会启动一个子线程，在子线程中生成RDB快照文件，所以不会阻塞主线程


redis还可以通过配置文件的选项来实现隔一段时间就执行一次bgsave
```
save 800 1 //意思是800秒之内至少对数据库修改了1次，就会执行bgsave
```

这里需要提一点的是RDB快照是**全量快照**，每次执行RDB快照都是将内存中**所有数据**写入磁盘
如果操作太频繁会对Redis性能产生影响，但是如果频率太低，数据丢失的也会更多，概率也就更大

所以为了应对RDB的缺点，Redis引入了AOF持久化功能
