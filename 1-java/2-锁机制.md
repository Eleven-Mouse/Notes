## 一，概念
锁就是控制多线程并发访问共享资源的规则，目的是保证线程安全，避免数据错乱，并发问题

----

>java里面的锁可以大致分类两大类：1，JVM层面的锁。2，jdk包提供的锁
## 二，synchronized
它是java内置的关键字，属于jvm层面的锁，也叫内置锁，监视器锁

它的作用很简单：同一时间只有一个线程能进入被锁住的代码块或方法

- 使用
  ```
  1,public synchronized void method() //同步方法
  2,synchronized(obj)  //同步代码块
  3,public static  synchronized void staticMethod()  //同步静待方法
  ```


----

  - 底层原理
		通过对象头里面的mark word 记录锁状态，JVM会自动完成加锁，释放锁，甚至异常时也会自动释放，非常安全

-----

- 锁膨胀机制
		早期的 synchronized 是重量级锁，效率非常低，但是在jdk1.6之后引入了锁膨胀机制，效率大幅提升
	过程：
	```
	
	无锁状态  ----> 第一个线程过来，将线程ID存入对象头，下次同样的线程过来，直接就能获取锁，无需枪锁
	------> 有第二个线程来抢锁，偏向锁失效，升级为轻量锁，用CAS自旋尝试获取锁 ------> 自旋多次还拿不到
	锁，升级为重量级锁，线程阻塞，进入内核态等待
	```
	>锁升级的整个过程只会升级，不会降级
	
-----
## 三，lock接口
lock接口是jdk并发包提供的锁，它是手动锁，比 synchronized 更灵活，
lock接口的主要实现类是 ReentrantLock，可重入锁，它和 synchronized 的功能类似，但是优势很明显
	1，支持手动加锁，手动释放，更灵活
	2，支持超时获取锁，拿不到就放弃，不会死等
	3，支持终端获取锁，线程可以被打断
	4，支持公平锁和非公平锁切换
	5，可以绑定多个Condition，实现精准唤醒
	
------
- 使用
	```
	
	Lock lock = new ReentrantLock();
	lock.lock();
	try{
		//业务逻辑
	}
	finally{
		unlock();
	}
	
	```

## 四，公平锁与非公平锁

|     | 非公平锁                          | 公平锁                     |
| --- | ----------------------------- | ----------------------- |
| 概念  | 线程来抢锁，不排队，直接cas自旋尝试，没抢到锁，才去排队 | 线程严格按照先来后到的顺序进行排队，先来先服务 |
| 优点  | 响应快，吞吐量高                      | 避免饥饿                    |
| 缺点  | 可能产生线程饥饿                      | 效率低，吞吐量小                |

-----

## 五，可重入锁
同一线程可以多次获取同一把锁，不会自己把自己锁死，ReentrantLock 和 synchronized 都是可重入锁

- 原理
		锁内部维护一个计数器，加锁一次+1，释放一次-1，计数器为0，才真正释放锁

------

## 六，读写锁-ReadWriteLock
读锁共享，多个线程同时持有读锁，不互斥
写锁互斥，线程持有写锁，其他线程读写操作均被阻塞

适用于读多写少的场景

------
## 七，悲观锁与乐观锁
>这是两种思想，不是具体的锁


|      | 悲观锁                        | 乐观锁                                 |
| ---- | -------------------------- | ----------------------------------- |
| 概念   | 认为一定会发生并发冲突，所以先加锁，再操作      | 认为一般不会冲突，不加锁，直接操作，最后用版本号或CAS检查是否被修改 |
| 代表实现 | synchronized，ReentrantLock | CAS，AtomicInteger等原子类               |
| 适用场景 | 数据竞争激烈                     | 读多写少，冲突少的场景，性能极高                    |
