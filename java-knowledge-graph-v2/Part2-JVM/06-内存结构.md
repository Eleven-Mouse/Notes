## 一、知识树

```
JVM 内存结构
├── 线程私有
│   ├── 程序计数器（PC Register）
│   ├── 虚拟机栈（VM Stack）
│   └── 本地方法栈（Native Method Stack）
├── 线程共享
│   ├── 堆（Heap）
│   └── 方法区 / 元空间（Metaspace）
└── 直接内存（Direct Memory）
```

## 二、核心知识点

### 1. 程序计数器（PC Register）

| 属性 | 说明 |
|------|------|
| 线程私有 | 每条线程都有自己的 PC |
| 作用 | 记录当前执行的字节码指令地址（行号） |
| 执行 native 方法时 | 计数器值为 `undefined` |
| **唯一不会 OOM 的区域** | JVM 规范中没有规定任何 OutOfMemoryError |

**面试官关注点**: 为什么不会 OOM？——因为 PC 只存一个地址，大小固定，不会随程序运行增长。

### 2. 虚拟机栈（VM Stack）

**栈帧结构**（每个方法调用 = 一个栈帧）：

```
栈帧
├── 局部变量表    → 存方法参数 + 局部变量（slot 为单位，long/double 占 2 个 slot）
├── 操作数栈      → 方法执行的工作区，算术运算/方法调用的参数传递
├── 动态链接      → 指向运行时常量池的方法引用（支持多态）
└── 方法返回地址   → 方法正常退出或异常退出后，返回到调用者的地址
```

**异常对比**:

| 异常 | 触发条件 | 典型场景 |
|------|----------|----------|
| `StackOverflowError` | 栈深度超过限制 | 递归调用无终止条件 |
| `OutOfMemoryError` | 栈无法扩展（动态扩展时内存不足） | 线程数过多，每个线程都分配栈空间 |

> **参数**: `-Xss256k` 设置每个线程的栈大小（默认 1MB）

**面试陷阱**: StackOverflowError 不是 OOM，面试时别搞混。栈溢出一般找递归/死循环。

### 3. 本地方法栈

- 为 Native 方法（如 `Object.hashCode()` 的 C++ 实现）服务
- HotSpot 把虚拟机栈和本地方法栈合二为一
- 同样会抛出 StackOverflowError 和 OutOfMemoryError

### 4. 堆（Heap）

**核心分区**:

```
堆
├── 新生代（Young Generation）  — 默认堆的 1/3
│   ├── Eden 区                  — 新对象优先分配
│   ├── Survivor 0（From）       — Minor GC 后存活对象
│   └── Survivor 1（To）         — Minor GC 后存活对象
└── 老年代（Old Generation）     — 默认堆的 2/3
```

> **比例**: Eden : S0 : S1 = 8 : 1 : 1（默认），新生代 : 老年代 = 1 : 2（默认）

**TLAB（Thread Local Allocation Buffer）**:
- Eden 区中为每条线程分配的私有分配缓冲区
- 避免多线程并发分配对象时的锁竞争
- 对象分配流程：TLAB → Eden（CAS）→ 老年代（大对象）

**对象分配策略速记**:
1. 新对象优先在 Eden 分配（TLAB 加速）
2. 大对象（超阈值 `-XX:PretenureSizeThreshold`）直接进老年代
3. 长期存活对象（年龄 ≥ 15，默认）晋升老年代
4. Survivor 中同龄对象超空间一半，直接晋升（动态年龄判断）

### 5. 方法区 / 元空间

**JDK 版本演进（面试高频考点）**:

| 对比项 | JDK 7（永久代） | JDK 8+（元空间） |
|--------|-----------------|-------------------|
| 存储位置 | JVM 堆中的一部分 | 本地内存（Native Memory） |
| 大小限制 | 受 `-XX:MaxPermSize` 限制 | 受物理内存限制（默认无上限） |
| 字符串常量池 | 永久代 | **移到堆中** |
| 运行时常量池 | 永久代 | 元空间 |
| OOM 风险 | `PermGen space` | `Metaspace` |

**为什么移除永久代?**
1. 永久代大小固定，容易 OOM（特别是 CGLib 等动态生成大量类的场景）
2. 合并 JRockit 虚拟机（JRockit 没有永久代概念）
3. 字符串常量池放堆中更容易被 GC 回收

> **参数**: `-XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=256m`

### 6. 直接内存

- 不属于 JVM 规范中的运行时数据区，但会被使用
- NIO 的 `DirectByteBuffer` 通过 `Unsafe` 类直接分配 Native 内存
- 不受堆大小限制，但受物理内存限制
- **OOM 表现**: `Direct buffer memory`
- 垃圾回收：只有当 DirectByteBuffer 对象被回收时，才会通过 Cleaner 释放

> **参数**: `-XX:MaxDirectMemorySize=256m`

## 三、各区域异常汇总

| 区域 | 异常类型 | 典型原因 |
|------|----------|----------|
| 堆 | `java.lang.OutOfMemoryError: Java heap space` | 内存泄漏 / 对象太多 / 堆太小 |
| 堆 | `java.lang.OutOfMemoryError: GC overhead limit exceeded` | GC 回收了但内存仍不够（98% 时间花在 GC） |
| 栈 | `java.lang.StackOverflowError` | 递归太深 / 方法调用链过长 |
| 栈 | `OutOfMemoryError: unable to create native thread` | 线程数太多 |
| 元空间 | `java.lang.OutOfMemoryError: Metaspace` | 动态生成类太多（如 CGLib） |
| 直接内存 | `java.lang.OutOfMemoryError: Direct buffer memory` | NIO 使用不当，未释放 |

## 四、面试题

### Q1: 描述一下 JVM 的内存结构？

```
答: JVM 内存分为线程私有和线程共享两部分。线程私有包括程序计数器（记录字节码行号）、虚拟机栈（每个方法一个栈帧）和本地方法栈。线程共享包括堆（对象实例）和方法区/元空间（类信息、常量池）。此外还有直接内存，供 NIO 使用。
```
### Q2: 程序计数器为什么不会 OOM？

```
答: PC 只存储当前字节码指令的地址，占用固定大小的内存空间（一个字长），不会随程序运行增长，所以 JVM 规范中没有为其规定任何 OOM 情况。
```
### Q3: 栈和堆的区别是什么？

```
答: 栈是线程私有的，存储局部变量和方法调用信息，自动管理（方法结束自动释放），空间小但速度快。堆是线程共享的，存储对象实例和数组，由 GC 管理，空间大但分配速度相对慢。栈溢出是 StackOverflowError，堆溢出是 OutOfMemoryError。
```
### Q4: JDK 8 为什么用元空间替代永久代？

```
答: 三个原因——
	(1) 永久代大小固定，容易在动态生成类场景下 OOM；
	(2) 为了和 JRockit 合并（JRockit 没有永久代）；
	(3) 元空间使用本地内存，大小灵活，不容易溢出。另外字符串常量池从永久代移到了堆中，方便 GC 管理。
```
### Q5: 新对象一定分配在 Eden 区吗？

```
答: 不一定。有两种例外：
	(1) 大对象（超过 `-XX:PretenureSizeThreshold` 设置的阈值）直接分配在老年代；
	(2) 如果启用 TLAB，优先在 TLAB 中分配，TLAB 在 Eden 区内部。
```
### Q6: 什么情况下栈会 OOM？什么情况下是 StackOverflow？

```
答: StackOverflow 是单个线程的栈深度超限，最常见于递归无终止条件。栈 OOM 是 JVM 无法为新线程分配栈空间（通常因为创建了太多线程），异常信息是 `unable to create native thread`。
```
### Q7: 字符串常量池在 JDK 6、7、8 分别在哪里？

```
答: JDK 6 在永久代。JDK 7 移到了堆中（但运行时常量池仍在永久代）。JDK 8 字符串常量池在堆中，运行时常量池在元空间。
```
### Q8: TLAB 是什么？为什么需要它？

```
答: TLAB（Thread Local Allocation Buffer）是 Eden 区中为每个线程划分的私有分配缓冲区。多线程并发分配对象时，使用 TLAB 可以避免对 Eden 区加锁，提高分配效率。TLAB 占满后才需要在 Eden 区用 CAS 分配。
```

### Q9： 堆内存又可以细分为哪些部分
```
答：堆又分为 “老年代” 和 “新生代”
	新 new 出来的对象一般都在新生代eden区，miner GC存活的对象进入S0区，有一次存活进入S1区，直到年龄超过15（默认）进入老年代，
```

## 五、常见误区

| 误区 | 正确理解 |
|------|----------|
| 方法区就是永久代 | 方法区是规范，永久代是 HotSpot 的实现；JDK 8 换成了元空间 |
| 栈溢出等于 OOM | StackOverflowError 和 OOM 是不同类型的错误 |
| 所有对象都在堆上 | 随着逃逸分析（JIT），未逃逸的对象可能栈上分配 |
| 元空间不会 OOM | 元空间使用本地内存，同样会 OOM |
| Survivor 区是必需的 | `-XX:-UseSurvivorSpace` 可以关闭，对象直接从 Eden 到老年代 |

## 六、实战场景

1. **OOM 排查**: `java.lang.OutOfMemoryError: Java heap space` → 先 `-XX:+HeapDumpOnOutOfMemoryError` 导出 dump，用 MAT 分析
2. **栈溢出排查**: 看异常堆栈，找到递归调用链，加终止条件
3. **Metaspace OOM**: 检查是否有大量动态代理（CGLib/ByteBuddy），适当增大 MetaspaceSize
4. **线程数过多**: 调小 `-Xss` 或限制线程池大小

## 七、对象内存布局（加分项）

一个对象在内存中的布局分为三部分：

| 部分 | 说明 | 细节 |
|------|------|------|
| 对象头（Header） | Mark Word + 类型指针 | Mark Word 存储 hashCode、GC 年龄、锁状态；类型指针指向类元数据 |
| 实例数据（Instance Data） | 对象真正存储的信息 | 各字段（包括从父类继承的），受 `-XX:FieldsAllocationStyle` 影响 |
| 对齐填充（Padding） | 补齐到 8 字节整数倍 | HotSpot 要求对象大小必须是 8 的倍数 |

**指针压缩（Compressed Oops）**:
- 堆 < 32G 时，JVM 默认开启指针压缩（`-XX:+UseCompressedOops`）
- 将 64 位指针压缩为 32 位，节省约 50% 的内存
- 超过 32G 后指针压缩失效，内存反而可能"缩水"

> **面试加分**: 为什么建议堆大小不要超过 32G？——超过 32G 后指针压缩失效，同样大小的堆实际可用空间反而减少。

## 八、栈帧执行流程（结合字节码理解）

```java
public int add(int a, int b) {
    int c = a + b;
    return c;
}
```

对应字节码执行时栈帧变化：
```
1. iload_1      → 操作数栈压入 a（局部变量表 slot 1）
2. iload_2      → 操作数栈压入 b（局部变量表 slot 2）
3. iadd         → 弹出 a 和 b，计算结果压栈
4. istore_3     → 弹出结果存入 slot 3（即变量 c）
5. iload_3      → 将 c 压入操作数栈
6. ireturn      → 返回操作数栈顶的值
```
