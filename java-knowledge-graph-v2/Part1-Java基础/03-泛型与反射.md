## 一、泛型

### 1.1 知识树

```
泛型
├── 泛型类 / 泛型方法 / 泛型接口
├── 类型擦除（核心）
├── 通配符（? extends / ? super）
├── PECS 原则
├── 泛型边界（上界 <T extends X> / 下界 <? super X>）
├── 泛型与数组
└── 泛型的局限（不能 new T / 不能 instanceof）
```

### 1.2 类型擦除（面试必问）

```java
// 编译前
List<String> list1 = new ArrayList<>();
List<Integer> list2 = new ArrayList<>();
list1.getClass() == list2.getClass();  // true！运行时是同一个类

// 擦除规则：
// <T> → Object
// <T extends X> → X
// <? extends X> → X
// <? super X> → Object
```

**类型擦除的完整过程：**

```java
// 源码
public class Box<T extends Comparable<T>> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

// 擦除后（T 的上界是 Comparable）
public class Box {
    private Comparable value;
    public void set(Comparable value) { this.value = value; }
    public Comparable get() { return value; }
}

// 调用处编译时插入类型转换
Box<String> box = new Box<>();
box.set("hello");
String s = box.get();
// 编译后：String s = (String) box.get();  // 自动插入强转
```

**桥方法（Bridge Method）：**

```java
// 子类
class StringBox extends Box<String> {
    @Override
    public void set(String value) { ... }  // 重写
}

// 擦除后父类方法签名变为 set(Comparable)
// 子类的 set(String) 签名不同 → 不是重写！

// 编译器自动生成桥方法：
public void set(Comparable value) {
    set((String) value);  // 转发到实际方法
}
```

### 1.3 通配符与 PECS

```java
// ? extends T（上界通配符）— Producer
List<? extends Number> list = new ArrayList<Integer>();
Number n = list.get(0);      // ✅ 读出来一定是 Number 或子类
list.add(new Integer(1));    // ❌ 编译器不知道具体是哪个子类

// ? super T（下界通配符）— Consumer
List<? super Integer> list = new ArrayList<Number>();
list.add(new Integer(1));    // ✅ Integer 是任何超类的子类，可以安全加入
Object o = list.get(0);      // ✅ 但只能当 Object 拿出来
Number n = list.get(0);      // ❌ 编译器不知道具体是哪个超类

// PECS 原则：Producer Extends, Consumer Super
// 如果只从集合中读取 → ? extends T
// 如果只往集合中写入 → ? super T
// 如果既读又写 → 不用通配符，用 <T>
```

**PECS 实战示例：**

```java
// Collections.copy 方法签名完美体现 PECS
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    // src 是 Producer → ? extends T（只读）
    // dest 是 Consumer → ? super T（只写）
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}
```

### 1.4 泛型的局限

```java
// 1. 不能 new T()
T obj = new T();  // 编译报错（擦除后不知道 T 是什么）

// 解决：传入 Class<T> 用反射创建
public <T> T create(Class<T> clazz) throws Exception {
    return clazz.getDeclaredConstructor().newInstance();
}

// 2. 不能 new T[]
T[] array = new T[10];  // 编译报错

// 解决：(Object[]) 强转 或 反射 Array.newInstance

// 3. 不能 instanceof
if (obj instanceof T) { }  // 编译报错（擦除后 T 不存在）

// 4. 不能用于静态上下文
static T value;  // 编译报错（静态属于类，不属于实例，T 未确定）

// 5. 基本类型不能做泛型参数
List<int> list;   // 编译报错
List<Integer> list; // OK
```

## 二、反射

### 2.1 知识树

```
反射
├── Class 对象获取（3种方式）
├── 获取字段 / 方法 / 构造器
├── setAccessible(true) 突破 private
├── 反射创建对象
├── 反射调用方法
├── 反射读取注解
├── 性能开销分析
└── 反射在框架中的应用
```

### 2.2 Class 对象获取

```java
// 方式 1：类名.class（编译时已知）
Class<?> clazz1 = User.class;

// 方式 2：对象.getClass()（运行时已知）
User user = new User();
Class<?> clazz2 = user.getClass();

// 方式 3：Class.forName()（全限定名，配置文件中读取）
Class<?> clazz3 = Class.forName("com.example.User");

// 基本类型的 Class
Class<?> intClass = int.class;       // 基本类型
Class<?> integerClass = Integer.class; // 包装类型
intClass == integerClass;  // false
```

### 2.3 反射核心操作

```java
Class<?> clazz = Class.forName("com.example.User");

// 获取字段
Field nameField = clazz.getDeclaredField("name");
nameField.setAccessible(true);  // 突破 private 限制

// 获取方法
Method setNameMethod = clazz.getDeclaredMethod("setName", String.class);
setNameMethod.setAccessible(true);

// 获取构造器
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class, int.class);
constructor.setAccessible(true);

// 反射创建对象
Object instance = constructor.newInstance("Alice", 25);

// 反射调用方法
setNameMethod.invoke(instance, "Bob");

// 反射读写字段
nameField.set(instance, "Charlie");
String name = (String) nameField.get(instance);

// 读取注解
Field field = clazz.getDeclaredField("name");
MyAnnotation anno = field.getAnnotation(MyAnnotation.class);
```

### 2.4 反射在框架中的应用

```
Spring IOC：
  1. Class.forName(className) 加载 Bean 的类
  2. clazz.getDeclaredConstructor().newInstance() 创建实例
  3. field.set(instance, dependency) 注入依赖（@Autowired）

MyBatis：
  1. 反射读取实体类字段和注解
  2. 反射创建结果对象
  3. 反射 set 属性值

JDK 动态代理：
  1. Proxy.newProxyInstance() 创建代理对象
  2. InvocationHandler.invoke() 通过反射调用目标方法

Jackson / Gson：
  1. 反射获取所有字段
  2. 反射调用 getter 读取值 → 序列化
  3. 反射调用 setter 设置值 → 反序列化
```

### 2.5 反射的性能开销

```
为什么反射慢？
1. 安全检查（setAccessible 需要权限检查）
2. 方法查找（按名字搜索）
3. 参数装箱/拆箱
4. JIT 无法内联（编译期不知道调用目标）

性能对比（大约）：
  直接调用：1x
  反射调用：10~100x

优化手段：
1. 缓存 Method/Field 对象（不要每次 getDeclaredMethod）
2. setAccessible(true)（跳过安全检查，性能提升约 20-30%）
3. MethodHandle（JDK7+，比反射更接近底层）
4. 字节码生成（cglib / ByteBuddy，Spring AOP 使用）
```

## 三、面试题精选

### Q1：什么是泛型擦除？有什么影响？
```
Java 泛型在编译时进行类型检查，编译后擦除为原始类型（Object 或上界）

影响：
1. 运行时无法获取泛型类型（list.getClass() 看不到 String）
2. 不能 new T() / instanceof T / new T[]
3. 方法重载冲突（擦除后签名相同）
4. 运行时通过桥方法维持多态
```

### Q2：List< Object > 和 List< ? > 的区别

```
List<Object>：可以 add 任何对象，但只能声明为 Object 类型
List<?>：未知类型，不能 add（除了 null），只能 get 为 Object

List<Object> list = new ArrayList<String>();  // 编译报错！泛型不支持协变
List<?> list = new ArrayList<String>();       
```
### Q3：反射能访问 private 字段吗？有什么问题？

可以：field.setAccessible(true) 突破访问控制

问题：
1. 破坏封装（违反 OOP 设计原则）
2. 安全管理器可能阻止（SecurityManager）
3. JDK9 模块化后，某些 private 访问需要 --add-opens
4. 性能开销
5. 代码脆弱（字段名改了反射代码就报错）
### Q4：如何在运行时获取泛型的实际类型？
```
通过匿名子类或 TypeToken 保留泛型信息：
// 方式 1：匿名子类
abstract class TypeRef<T> {}
TypeRef<List<String>> ref = new TypeRef<List<String>>() {};
Type type = ref.getClass().getGenericSuperclass();  // ParameterizedType
// 可以提取出 List<String>

// 方式 2：方法返回类型
Method method = MyClass.class.getMethod("getList");
Type returnType = method.getGenericReturnType();  // ParameterizedType

// Jackson 的 TypeReference 就是这个原理
```

### Q5：什么是 MethodHandle？和反射有什么区别？
```
MethodHandle（JDK7+）：方法句柄，更底层的动态调用机制

对比反射：
  反射：模拟 Java 代码层面的调用（Method.invoke）
  MethodHandle：模拟字节码层面的调用（invokedynamic）

优点：
  1. 类型安全（编译期检查方法签名）
  2. 性能更好（可以直接内联）
  3. 支持调用私有方法（Find & Bind）

但实际开发中很少直接使用，主要在 JVM 语言（Kotlin/Groovy）和框架中使用
```

### Q6：在使用泛型时，通配符 < ? extends T> 和 < ? super T> 有什么区别？

>1. < ? extends T> 表示通配符上限，只能接收T类型或T的子类。“读多写少”，只能安全读取T及其子类的元素，但不能往里面加任意元素
		比如 List< ? extends Number> 可以接收 List< Integer > 或 List< Double > 。
		
 >1. < ? super T> 是通配符下限，只能接收T类型或T的父类，“写多读少”可以安全写入T及其子类的元素，但读取时只能拿到Object类型，没办法拿到具体的子类类型
		比如 List< ? super Integer> 可以接收 List< Number > 或 List< Object > 。

**简单记就是“extens取，super加”**
### Q7：通过java反射机制可以实现什么功能？

>反射能在运行时获取类的信息，比如方法、字段，还能动态调用方法、修改字段值。
	例如：
		1. 自定义注解；
		2. Spring的依赖注入；
		3. ORM框架的对象关系映射；
