## 二、核心知识点

### 2.1 ThreadPoolExecutor 7 大参数

```java
public ThreadPoolExecutor(
    int corePoolSize,        // 核心线程数（常驻不销毁）
    int maximumPoolSize,     // 最大线程数
    long keepAliveTime,      // 非核心线程空闲存活时间
    TimeUnit unit,           // 存活时间单位
    BlockingQueue<Runnable> workQueue,  // 任务等待队列
    ThreadFactory threadFactory,        // 线程工厂（自定义线程名）
    RejectedExecutionHandler handler    // 拒绝策略
)
```

| 参数 | 说明 | 注意 |
|------|------|------|
| corePoolSize | 核心线程数，即使空闲也不回收（除非设置 allowCoreThreadTimeOut） | 不宜过大 |
| maximumPoolSize | 最大线程数，包含核心线程 | 必须 >= corePoolSize |
| keepAliveTime | 非核心线程空闲超过此时间被回收 | 配合 unit 使用 |
| unit | 时间单位 | — |
| workQueue | 任务队列，保存等待执行的任务 | 选择很重要 |
| threadFactory | 创建线程的工厂 | 建议自定义线程名便于排查 |
| handler | 拒绝策略，队列满且线程数达到最大时的处理 | 根据业务选择 |

**常见队列选择**：
- LinkedBlockingQueue：无界（默认 Integer.MAX_VALUE，危险）
- ArrayBlockingQueue：有界（推荐，需指定容量）
- SynchronousQueue：不存储任务，直接交给线程（CachedThreadPool 用）
- PriorityBlockingQueue：支持优先级排序

### 2.2 执行流程（必背）

```
提交任务 execute(task)
      │
      ▼
 当前线程数 < corePoolSize？
      │
      ├── 是 → 创建核心线程执行任务
      │
      └── 否 → 任务放入 workQueue
                    │
                    ├── 放入成功 → 等待核心线程空闲来取
                    │
                    └── 放入失败（队列满了）→
                              │
                              ▼
                    当前线程数 < maximumPoolSize？
                              │
                              ├── 是 → 创建非核心线程执行任务
                              │
                              └── 否 → 执行拒绝策略 handler
```

**简记口诀**：核心线程 → 队列 → 非核心线程 → 拒绝策略

**核心考点**：先放队列再创建非核心线程！不是先创建到最大线程数再放队列。

---

### 2.3 四种拒绝策略

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| AbortPolicy（默认） | 抛出 RejectedExecutionException | 需要感知任务丢失 |
| CallerRunsPolicy | 由提交任务的线程自己执行 | 不想丢弃任务，降低提交速度 |
| DiscardPolicy | 默默丢弃任务，不抛异常 | 可容忍丢失 |
| DiscardOldestPolicy | 丢弃队列头部最旧的任务，重新提交当前任务 | 优先新任务 |

```java
// 自定义拒绝策略
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4, 8, 60, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100),
    new ThreadPoolExecutor.CallerRunsPolicy() // 调用者自己执行
);
```

### 2.4 四种常见线程池及问题

| 线程池 | 创建方式 | 特点 | 问题 |
|--------|---------|------|------|
| FixedThreadPool | Executors.newFixedThreadPool(n) | 固定 n 个线程，无界队列 | **队列无界，可能 OOM** |
| CachedThreadPool | Executors.newCachedThreadPool() | 核心线程 0，最大 Integer.MAX_VALUE | **线程数不可控，可能 OOM** |
| SingleThreadExecutor | Executors.newSingleThreadExecutor() | 单线程，无界队列 | **队列无界，可能 OOM** |
| ScheduledThreadPool | Executors.newScheduledThreadPool(n) | 定时/周期执行 | **队列无界，可能 OOM** |

```java
// FixedThreadPool 源码 —— 问题所在
public static ExecutorService newFixedThreadPool(int n) {
    return new ThreadPoolExecutor(n, n, 0L, TimeUnit.MILLISECONDS,
            new LinkedBlockingQueue<Runnable>()); // 无界队列！
}
```

---

### 2.5 为什么不推荐 Executors

**阿里巴巴 Java 开发手册强制规定**：

> 线程池不允许使用 Executors 去创建，而是通过 ThreadPoolExecutor 的方式。

| 问题线程池 | 风险 |
|-----------|------|
| FixedThreadPool / SingleThreadExecutor | LinkedBlockingQueue 默认容量 Integer.MAX_VALUE，任务堆积导致 OOM |
| CachedThreadPool | maximumPoolSize = Integer.MAX_VALUE，创建大量线程导致 OOM |
| ScheduledThreadPool | DelayedWorkQueue 无界，任务堆积导致 OOM |

**正确做法**：手动创建 ThreadPoolExecutor，明确指定队列容量和最大线程数。

### 2.6 线程池参数如何设定

**CPU 密集型**（计算为主，如加密、压缩）：
```
corePoolSize = CPU 核心数 + 1
// +1 是为了在某个线程偶尔因为缺页中断等原因暂停时，额外的线程能顶上
```

**IO 密集型**（网络请求、数据库、文件读写）：
```
corePoolSize = CPU 核心数 * 2
// 或更精确：CPU 核心数 / (1 - 阻塞系数)，阻塞系数一般取 0.8~0.9
// 例如 8 核：8 / (1 - 0.9) = 80
```

**实际经验**：
- 公式只是起点，最终要根据压测结果调整
- maximumPoolSize 一般设为 corePoolSize 的 2~3 倍
- 队列容量不宜过大（导致任务延迟高）也不宜过小（频繁触发拒绝策略）

### 2.7 线程池关闭

```java
// 温柔关闭：不再接受新任务，等已提交任务执行完
executor.shutdown();

// 强制关闭：尝试中断正在执行的任务，返回未执行的任务列表
List<Runnable> notExecuted = executor.shutdownNow();

// 优雅关闭的标准写法
executor.shutdown();
if (!executor.awaitTermination(60, TimeUnit.SECONDS)) {
    executor.shutdownNow();
}
```

| 方法 | 行为 | 新任务 | 已执行任务 | 队列中任务 |
|------|------|--------|-----------|-----------|
| shutdown() | 温柔关闭 | 拒绝 | 执行完 | 执行完 |
| shutdownNow() | 强制关闭 | 拒绝 | 尝试中断 | 返回不执行 |

---

### 2.8 线程池 5 种状态

```
RUNNING     → 接受新任务，处理队列任务
    │ shutdown()
    ▼
SHUTDOWN    → 不接受新任务，处理队列中的任务
    │ shutdownNow()
    ▼
STOP        → 不接受新任务，不处理队列，中断进行中的任务
    │ 队列和线程池都清空
    ▼
TIDYING     → 所有任务终止，workerCount=0
    │ terminated() 执行完
    ▼
TERMINATED  → 终止状态
```

### 2.9 线程池中的异常处理

```java
// 问题：线程池中任务抛出异常，线程不会自动通知调用者
executor.execute(() -> {
    throw new RuntimeException("任务异常"); // 异常被吞掉，看不到
});

// 解决方案一：try-catch 包住整个任务
executor.execute(() -> {
    try {
        // 业务逻辑
    } catch (Exception e) {
        log.error("任务执行异常", e);
    }
});

// 解决方案二：重写 afterExecute（ThreadPoolExecutor 钩子）
// 解决方案三：用 submit + Future.get() 获取异常
Future<?> future = executor.submit(() -> {
    throw new RuntimeException("任务异常");
});
try {
    future.get(); // 会抛出 ExecutionException，包含原始异常
} catch (ExecutionException e) {
    log.error("任务执行异常", e.getCause());
}
```

## 三、面试题

### Q1：线程池的执行流程？（高频）
>**答**：提交任务时，(1) 线程数 < corePoolSize → 创建核心线程执行；(2) 线程数 >= corePoolSize → 放入队列；(3) 队列满 → 线程数 < maximumPoolSize → 创建非核心线程执行；(4) 队列满且线程数达到 maximumPoolSize → 执行拒绝策略。

### Q2：为什么不推荐使用 Executors？
>**答**：FixedThreadPool 和 SingleThreadExecutor 使用无界队列（Integer.MAX_VALUE），任务堆积会导致 OOM。CachedThreadPool 最大线程数为 Integer.MAX_VALUE，高并发会创建大量线程导致 OOM。应该手动用 ThreadPoolExecutor 创建，明确指定参数。

### Q3：线程池参数怎么设置？
>**答**：CPU 密集型任务：核心线程数 = CPU 核心数 + 1；IO 密集型任务：核心线程数 = CPU 核心数 * 2 或 CPU 核心数 / (1 - 阻塞系数)。公式只是起点，需要通过压测最终确定。

### Q4：四种拒绝策略是什么？怎么选？
>**答**：AbortPolicy 抛异常（默认）；CallerRunsPolicy 调用者线程执行（降速）；DiscardPolicy 默默丢弃；DiscardOldestPolicy 丢弃最旧任务。一般推荐 CallerRunsPolicy，不会丢任务还能自动降速。

### Q5：shutdown 和 shutdownNow 的区别？
>**答**：shutdown 不接受新任务但执行完队列中的任务；shutdownNow 不接受新任务、不执行队列任务、尝试中断正在执行的任务。实际中一般先 shutdown 再 awaitTermination，超时后 shutdownNow。

### Q6：线程池中的核心线程会被回收吗？如果想让核心线程在空闲时也被回收，需要设置哪个参数？
>**答**：核心线程默认不会被回收，要让它们空闲时也被回收，需要设置`allowCoreThreadTimeOut(true)`，同时配合`keepAliveTime`和`unit`来指定空闲多久后回收。比如设置`keepAliveTime(5, TimeUnit.SECONDS)`，核心线程空闲 5 秒就会被回收。

### Q7：线程池中任务抛异常了怎么办？
>**答**：execute 提交的任务异常会被吞掉。三种处理方式：
>	(1) 任务内部 try-catch；
>	(2) 用 submit 提交，Future.get() 会抛出 ExecutionException；
>	(3) 自定义线程池重写 afterExecute 方法。

### Q8：FixedThreadPool 和 CachedThreadPool 的区别？
> **答**：1. FixedThreadPool 固定线程数，无界队列，适合负载较重的场景。
>	2. CachedThreadPool 核心线程为 0，最大线程无限制，60 秒空闲回收，适合大量短异步任务。
>	**两者都有 OOM 风险。**

### Q9：如何监控线程池？
>**答**：ThreadPoolExecutor 提供监控方法：getActiveCount()（活跃线程数）、getCompletedTaskCount()（已完成任务数）、getQueue().size()（队列中任务数）、getLargestPoolSize()（历史最大线程数）。可以定期打印这些指标做监控告警。

### Q10：线程池的工作线程是怎么创建和复用的？
>**答**：Worker 内部类继承 AQS，创建时绑定一个初始任务。Worker 线程启动后循环调用 getTask() 从队列取任务执行。没有任务时调用 poll(keepAliveTime) 阻塞等待，超时返回 null 则销毁非核心线程。核心线程通过 take() 一直等待。

## 四、常见误区

| 误区 | 正确理解 |
|------|---------|
| "线程数越多越好" | 过多线程导致 CPU 上下文切换开销增大 |
| "先创建最大线程再放队列" | 先放队列，队列满才创建非核心线程 |
| "Executors 创建很方便就用它" | 阿里规范禁止，OOM 风险 |
| "核心线程不会被回收" | allowCoreThreadTimeOut(true) 后可以 |
| "execute 和 submit 效果一样" | submit 返回 Future，异常处理方式不同 |
| "shutdown 会立即停止所有线程" | shutdown 只是标记状态，正在执行的任务会继续 |
