## 二、核心知识点

### 2.1 Thread vs Runnable vs Callable vs Future

| 维度 | Thread | Runnable | Callable | Future |
|------|--------|----------|----------|--------|
| 返回值 | 无 | 无 | 有（泛型） | 获取异步结果 |
| 异常 | 无 | 无 | 可抛出受检异常 | 可捕获异常 |
| 继承限制 | 单继承 | 函数式接口 | 函数式接口 | 接口 |
| 使用方式 | 继承重写run() | 实现run() | 实现call() | get()获取结果 |

```java
// 1. 继承 Thread
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Thread方式");
    }
}

// 2. 实现 Runnable（推荐）
Thread t = new Thread(() -> System.out.println("Runnable方式"));

// 3. Callable + FutureTask
FutureTask<String> futureTask = new FutureTask<>(() -> {
    return "Callable返回结果";
});
new Thread(futureTask).start();
String result = futureTask.get(); // 阻塞等待

// 4. CompletableFuture（JDK8+，更优雅）
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> {
    return "异步结果";
});
String result = cf.get();
```

**面试官视角**：问这题不是让你背 API，而是考察你是否理解「任务与执行分离」的设计思想。Runnable 比 Thread 好，因为它将任务（what）和执行（how）解耦。

### 2.2 线程的 6 种状态与状态转换

```
NEW ──start()──▶ RUNNABLE ──run()结束/异常──▶ TERMINATED
					 |
				 RUNNABLE ──获取锁失败──▶ BLOCKED ──获取锁成功──▶ RUNNABLE
					 |
				 RUNNABLE ──wait/join───▶ WAITING ──notify──────▶ RUNNABLE
					 |
				 RUNNABLE ──sleep超时───▶ TIMED_WAITING ──超时──▶ RUNNABLE

```

---

### 2.3 sleep vs wait vs join vs yield

| 特性 | sleep | wait | join | yield |
|------|-------|------|------|-------|
| 所属类 | Thread | Object | Thread | Thread |
| 释放锁 | **不释放** | **释放锁** | 释放锁（底层wait） | 不释放 |
| 使用位置 | 任意 | 必须在synchronized块 | 任意 | 任意 |
| 唤醒方式 | 超时自动 | notify/notifyAll/超时 | 被join的线程执行完 | 立即恢复就绪 |
| 用途 | 模拟延时/暂停 | 线程间通信 | 等待另一个线程完成 | 让出CPU时间片 |
| 锁依赖 | 无 | 必须先获取对象锁 | 无 | 无 |

```java
// sleep 不释放锁的证明
synchronized (lock) {
    Thread.sleep(1000); // 其他线程在此期间无法获取 lock
}

// wait 释放锁
synchronized (lock) {
    lock.wait(); // 释放 lock，其他线程可以获取
}
```

### 2.4 守护线程（Daemon Thread）

```java
Thread t = new Thread(() -> {
    while (true) {
        // 后台任务，如 GC 线程
    }
});
t.setDaemon(true); // 必须在 start() 前设置
t.start();
// 当所有用户线程结束，JVM 退出，守护线程随之销毁
```

**要点**：
- 守护线程为用户线程提供服务（如 GC、JIT 编译线程）
- JVM 退出条件：所有**非守护线程**结束
- 守护线程中 finally 不一定执行（JVM 直接退出）
- 不适合做 I/O 操作（可能被强行中断导致数据不一致）

---

### 2.5 线程中断（interrupt 机制）

```java
// 正确的中断方式：协作式，而非强制式
Thread t = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            // sleep/wait/join 被中断会抛异常，并清除中断标志
            Thread.currentThread().interrupt(); // 重新设置中断标志
            break;
        }
        // 执行任务
    }
});

t.interrupt(); // 设置中断标志位
```

**面试关键点**：
- interrupt() 不是强行停止线程，只是设置中断标志（协作式）
- 如果线程在 sleep/wait/join 状态，会抛 InterruptedException 并**清除中断标志**
- 正确做法：捕获 InterruptedException 后要重新 interrupt() 或直接退出

---

### 2.6 线程优先级（了解即可）

```java
t.setPriority(Thread.MAX_PRIORITY); // 10
t.setPriority(Thread.MIN_PRIORITY); // 1
t.setPriority(Thread.NORM_PRIORITY); // 5，默认
```

**结论**：优先级 1-10，但不同 OS 调度策略不同，Java 优先级不可靠，不要依赖它控制执行顺序。

---

### 2.7 为什么不推荐直接 new Thread

```java
// 每次都 new Thread 的问题：
new Thread(() -> handle(request)).start(); // 每个请求一个线程？
```

| 问题 | 说明 |
|------|------|
| 资源不可控 | 线程数无上限，可能 OOM |
| 创建销毁开销 | 线程创建需要分配栈内存（默认1MB），OS 层面也有开销 |
| 无法复用 | 线程用完即销毁，无法复用 |
| 无法管理 | 无法监控线程状态、无法统一关闭 |
| 无法拒绝 | 任务过多时无拒绝策略 |

**引出线程池**：用 ThreadPoolExecutor 统一管理线程的创建、复用、销毁和拒绝策略。

## 三、面试题

### Q1：Thread、Runnable、Callable 有什么区别？
>**答**：Thread 是类（单继承限制），Runnable 是接口（run 无返回值），Callable 是接口（call 有返回值可抛异常）。实际开发中推荐用 Runnable/Callable 分离任务定义，交给线程池执行。

### Q2：线程有哪些状态？BLOCKED 和 WAITING 有什么区别？
>**答**：6 种状态。BLOCKED 是等 synchronized 锁还没拿到，WAITING 是已拿到锁但主动调用 wait/park 放弃了执行权。

### Q3：sleep 和 wait 有什么区别？
>**答**：
>四大区别：
>	(1) sleep 属于 Thread，wait 属于 Object；
>	(2) sleep 不释放锁，wait 释放锁；
>	(3) sleep 到时间自动醒，wait 需要 notify；
>	(4) wait 必须在 synchronized 块中使用。

### Q4：如何正确停止一个线程？
>**答**：调用 interrupt() 设置中断标志，线程内部通过 isInterrupted() 配合检查。如果线程在阻塞状态被中断，catch InterruptedException 后要重新设置中断标志或退出。

### Q5：守护线程是什么？使用场景和注意事项？
>**答**：为其他线程提供后台服务的线程，如 GC 线程。当所有用户线程结束，JVM 退出，守护线程直接销毁。注意：finally 块可能不执行，不适合做关键 I/O 操作。

### Q6：为什么调用 start() 而不是 run() 启动线程？
>**答**：调用 start() 会创建新线程并让 JVM 调用 run()；直接调用 run() 只是普通方法调用，在当前线程执行，不创建新线程。

### Q7：线程的 start() 能调用两次吗？
>**答**：不能。start() 内部检查线程状态，如果线程已经启动过，抛出 IllegalThreadStateException。一个 Thread 对象只能 start 一次。

### Q8：yield 方法有什么用？实际中用得多吗？
>**答**：yield 提示调度器让出当前 CPU 时间片，让其他同优先级线程执行。但只是建议，调度器可能忽略。实际开发中极少使用，调试测试时偶尔用到。

### Q9：线程安全问题，该如何去预防
>什么是线程安全问题：
>	多个线程去访问并修改同一个共享资源，而且这个修改操作不是**原子性**的，就容易发生线程安全问题
>解决：
>	将非原子操作变成原子操作
>	 例如：加锁（synchronized），JUC中Atomic系列类

## 四、常见误区

| 误区 | 正确理解 |
|------|---------|
| "stop() 可以停线程" | stop 已废弃，会强行释放锁导致数据不一致 |
| "interrupt 会立即停线程" | interrupt 只是设标志，协作式 |
| "sleep 会释放锁" | sleep 不释放任何锁 |
| "wait 不需要锁" | wait 必须在 synchronized 块中 |
| "线程优先级越高越先执行" | 优先级只是建议，OS 可能忽略 |
| "守护线程的 finally 一定执行" | JVM 退出时守护线程直接被杀，finally 不一定执行 |

## 五、实战场景

1. **Web 服务器**：每个请求一个线程（Tomcat NIO 模型之前）→ 进化为线程池 + NIO
2. **异步任务**：Callable + Future 获取异步结果 → CompletableFuture 链式调用
3. **心跳检测**：守护线程定时发送心跳包
4. **优雅停机**：用 interrupt + isInterrupted 配合退出循环
