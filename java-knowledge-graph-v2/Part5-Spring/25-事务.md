## 二、@Transactional 核心属性

```java
@Transactional(
    propagation = Propagation.REQUIRED,      // 传播行为
    isolation = Isolation.DEFAULT,            // 隔离级别
    rollbackFor = Exception.class,            // 回滚条件
    noRollbackFor = BusinessException.class,  // 不回滚条件
    timeout = 30,                             // 超时（秒）
    readOnly = false                          // 是否只读
)
public void transfer(Long fromId, Long toId, BigDecimal amount) {
    // 业务逻辑
}
```

| 属性 | 默认值 | 说明 |
|-----|-------|------|
| **propagation** | REQUIRED | 事务传播行为 |
| **isolation** | DEFAULT（使用数据库默认） | 事务隔离级别 |
| **rollbackFor** | RuntimeException + Error | 哪些异常回滚 |
| **noRollbackFor** | 无 | 哪些异常不回滚 |
| **timeout** | -1（无超时） | 超时时间（秒） |
| **readOnly** | false | 只读事务（查询优化） |

**关键注意：** 默认只对 RuntimeException 和 Error 回滚，**checked Exception（如 IOException）不回滚**！

```java
// 错误：IOException 不会回滚
@Transactional
public void process() throws IOException { ... }

// 正确：指定所有异常都回滚
@Transactional(rollbackFor = Exception.class)
public void process() throws IOException { ... }
```

## 三、7 种传播行为详解

| 传播行为 | 说明 | 有事务时 | 无事务时 |
|---------|------|---------|---------|
| **REQUIRED**（默认） | 需要事务 | 加入当前事务 | 新建事务 |
| **REQUIRES_NEW** | 必须新事务 | 挂起当前，新建事务 | 新建事务 |
| **NESTED** | 嵌套事务 | 在当前事务中创建保存点 | 新建事务 |
| **SUPPORTS** | 支持事务 | 加入当前事务 | 非事务执行 |
| **NOT_SUPPORTED** | 不支持事务 | 挂起当前事务 | 非事务执行 |
| **MANDATORY** | 强制事务 | 加入当前事务 | 抛出异常 |
| **NEVER** | 绝不用事务 | 抛出异常 | 非事务执行 |

### 3.1 REQUIRED（最常用）

```java
@Service
public class OrderService {
    @Transactional // 事务A
    public void createOrder() {
        orderDao.save(order);
        inventoryService.deduct(order); // 加入事务A
        pointsService.addPoints(user);  // 加入事务A
    }
}
// 任何一步失败，整个事务回滚
```

### 3.2 REQUIRES_NEW（独立事务）

```java
@Service
public class OrderService {
    @Transactional // 事务A
    public void createOrder() {
        orderDao.save(order);
        logService.saveLog(); // REQUIRES_NEW → 事务B（独立）
    }
}

@Service
public class LogService {
    @Transactional(propagation = Propagation.REQUIRES_NEW) // 独立事务B
    public void saveLog() {
        // 即使外部事务A回滚，日志也会保存
    }
}
```

### 3.3 NESTED（嵌套事务）

```java
@Service
public class OrderService {
    @Transactional // 外层事务
    public void createOrder() {
        orderDao.save(order);
        try {
            inventoryService.deduct(); // NESTED → 创建保存点
        } catch (Exception e) {
            // 库存扣减失败，回滚到保存点，不影响订单创建
            log.warn("库存扣减失败", e);
        }
    }
}

@Service
public class InventoryService {
    @Transactional(propagation = Propagation.NESTED) // 嵌套事务
    public void deduct() {
        inventoryDao.deduct();
    }
}
```

**NESTED vs REQUIRES_NEW：**
- NESTED：外层回滚时嵌套也回滚，嵌套回滚不影响外层
- REQUIRES_NEW：两个事务完全独立，互不影响

## 四、声明式事务底层原理

```
@Transactional 方法被调用
   │
   ▼
AOP 代理拦截（TransactionInterceptor）
   │
   ▼
TransactionAspectSupport.invokeWithinTransaction()
   │
   ▼
1. 获取事务属性（TransactionAttribute）
2. 获取事务管理器（PlatformTransactionManager）
3. 创建事务（getTransaction）
   ├── REQUIRED + 无事务 → 新建连接，关闭自动提交
   ├── REQUIRED + 有事务 → 加入（使用同一连接）
   └── REQUIRES_NEW → 挂起旧事务，新建连接
4. 执行目标方法
   ├── 成功 → commit()
   └── 异常 → 判断 rollbackFor → rollback()
5. 清理事务（恢复挂起的事务等）
```

### 场景1：同类内部方法调用（最常见）

### 场景2：方法非 public → Spring AOP 默认只代理 public 方法。

### 场景3：异常被 catch 吞掉

```java
// 异常被吞掉，Spring 以为正常返回 → 不回滚
// 解决：catch 中 setRollbackOnly() 或重新 throw

### 场景4：rollbackFor 配置错误 → 默认只回滚 RuntimeException，checked Exception 不回滚。正确：`@Transactional(rollbackFor = Exception.class)`

## 六、编程式事务（TransactionTemplate）

```java
@Autowired private TransactionTemplate transactionTemplate;

public void createOrder() {
    transactionTemplate.execute(status -> {
        orderDao.save(order);
        inventoryDao.deduct(order);
        return true;  // 异常时 status.setRollbackOnly()
    });
}
```

声明式（@Transactional）侵入低但粒度粗；编程式侵入高但可精确控制事务边界，避免长事务。

## 七、事务 + 锁的注意事项

```java
// 错误：锁在事务外 → 释放锁时事务还没提交，其他线程读到旧数据
@Transactional
public synchronized void deductStock(Long productId, int quantity) { ... }

// 时序：线程A 释放锁 → [事务提交] → 线程B 获取锁读到旧库存！
// 正确：事务放在锁范围内（编程式事务）
public boolean deductStock(...) {
    synchronized (this) {
        return transactionTemplate.execute(status -> { /* ... */ });
    }
}
```

## 八、长事务问题

### 长事务的危害

| 问题 | 说明 |
|-----|------|
| **数据库连接占用** | 事务期间持有连接，连接池耗尽 |
| **锁持有时间长** | 行锁长时间不释放，阻塞其他事务 |
| **Undo Log 膨胀** | 大量修改操作的回滚日志占用空间 |
| **主从延迟** | 大事务导致 binlog 同步延迟 |

### 如何避免长事务

事务只包裹数据库操作，远程调用、耗时计算放在事务外面。用编程式事务精确控制范围，或开启事务日志监控：
```yaml
logging:
  level:
    org.springframework.transaction: DEBUG
```

## 九、常见误区

| 误区 | 正解 |
|-----|------|
| @Transactional 对所有异常都回滚 | 默认只回滚 RuntimeException 和 Error |
| 同类方法调用事务也生效 | 内部调用走 this，不经过代理，事务失效 |
| readOnly 只能用于查询 | 实际上也能写，但会提示优化（某些数据库会优化） |
| REQUIRES_NEW 和 NESTED 一样 | REQUIRES_NEW 完全独立事务，NESTED 是外事务的保存点 |
| 事务方法必须是 public | 是的，Spring AOP 默认只代理 public 方法 |

## 十、面试题

### Q1：@Transactional 失效的场景有哪些？
**答：** 6 种场景：1) 同类内部调用（不走代理）；2) 方法非 public；3) 异常被 catch 吞掉；4) rollbackFor 未包含 checked Exception；5) 数据库引擎不支持事务（MyISAM）；6) 类未被 Spring 管理。

### Q2：REQUIRED 和 REQUIRES_NEW 的区别？
**答：** REQUIRED 加入当前事务，不存在则新建；REQUIRES_NEW 始终新建独立事务，将当前事务挂起。REQUIRES_NEW 的内层事务提交/回滚不影响外层。适用于需要独立提交的场景（如操作日志）。

### Q3：NESTED 和 REQUIRES_NEW 有什么区别？
**答：** NESTED 在当前事务中创建保存点（Savepoint），内层回滚到保存点不影响外层，但外层回滚会连带内层一起回滚。REQUIRES_NEW 创建完全独立的新事务，内外层互不影响。

### Q4：声明式事务的原理是什么？
**答：** 基于 AOP 代理，TransactionInterceptor 拦截 @Transactional 方法调用，在方法执行前创建事务（获取连接、关闭自动提交），方法正常返回时提交，异常时根据 rollbackFor 判断是否回滚。

### Q5：事务中为什么不要有远程调用？
**答：** 远程调用耗时长（网络IO），会导致事务持有数据库连接和锁的时间变长，造成连接池耗尽、锁阻塞等问题。应该将远程调用放在事务外面。

### Q6：@Transactional(rollbackFor = Exception.class) 的作用？
**答：** 默认 Spring 只对 RuntimeException 和 Error 回滚。加上 rollbackFor = Exception.class 让所有异常（包括 checked Exception 如 IOException）都触发回滚。

### Q7：synchronized + @Transactional 有什么问题？
**答：** 如果 synchronized 在事务外面，锁释放了但事务还没提交，其他线程获取锁后读到的是未提交的数据。解决方法是把事务放在锁范围内，或使用分布式锁。

### Q8：编程式事务和声明式事务怎么选？
**答：** 大部分场景用声明式事务（简单、侵入性低）。需要精确控制事务范围（避免长事务）、在非 public 方法中使用事务、或需要避免代理失效时使用编程式事务（TransactionTemplate）。
